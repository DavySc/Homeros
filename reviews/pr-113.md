## Findings

### B1 (blocking): stack over-read when the URI is long

`drive.c:42-45`: `char p[160]` takes the request params by `snprintf`,
whose return value `k` is the untruncated length, and `lsp_send` copies `k`
bytes from `p`. The fixed text is 61 bytes, so a file URI of about 99 bytes
(a path of about 91, fewer with spaces or non-ASCII, which percent-encode
to 3 bytes) reads past `p`; without sanitizers the stack bytes go to Lean
as JSON.

Repro (measured, 1 run, real Lean): `reviews/pr-113-repro/long-path.sh`
with the ASan build, project at a 99-byte path, `g 1 2`:

    ERROR: AddressSanitizer: stack-buffer-overflow ...
    READ of size 179 ...
      #2 str_add src/str/str.c:24
      #3 lsp_send src/lsp/lsp.c:739
    ... in stack of ... on_in src/infoview/oracle/drive.c:58

Main's old driver (`lsp_ask`, which builds into a `Str`) has no such limit
(measured by the Fable agent, 1 run). The same request at the short path
answers the goal.

Fix: build the params in a `Str` with `str_addf`, as `infoview.c` does for
its requests (`reviews/pr-113-repro/fix.diff`, same line count). With it the
long path answers the goal under ASan and the oracle agrees 37 of 37 there
(table above).

### N1 (not blocking, suggested): an error answer prints an empty goal

`goal()` prints `goal`, `""`, `\x04` when the answer has no `result` (an
error answer) or `m` is NULL (the server died with the request pending).
The old driver printed nothing, so `oracle.mjs` timed out; now the oracle
compares `""` with the page, and where the page also shows nothing it
counts as agreement. Measured by the Fable agent with a stub server
answering `{"error":…}` (1 run); with real Lean I could not provoke it:
killing `lake serve` before `g` leaves no server, so `lsp_send` sends
nothing, and `g 99 0` gets a `result` ("no goals"). `fix.diff` returns
early when there is no `result` (two lines).

### Notes (no change asked)

- Two `g` lines before an answer now print two blocks in the server's
  order (the old driver cancelled the first); `oracle.mjs` asks one at a
  time. The stale-answer drop of `lsp_answer` is gone; the oracle makes no
  edit while a `g` is pending (from reading).
- Out-of-range `L` or `C` send different positions than before (the
  agent's table: `g 99 3` was `3:0`, now `99:0`); `oracle.mjs` never
  generates them.
- `drive.c:23`'s comment, "as lsp.c showed it for LSP_GOAL", names what PR
  111 deletes; "result.rendered" alone says it.
- Duplication: `core_line` then `lsp_u16(t, c < w ? c : w)` repeats
  `infoview.c:625-626`, and the params literal repeats `lsp_ask`'s. There
  is no shared helper for TextDocumentPositionParams; for a driver that
  `make` does not build this is acceptable. `make dupes` passes.
- The `reviews/pr-43.md` fourth-pass section is PR 43's report commit
  `e77892e` riding along, as agreed; its checkable claims hold.
