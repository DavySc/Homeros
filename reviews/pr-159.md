# Review of PR 159: test_sql, our own cancel's reply without a server

**Verdict: approve.**

## What the change must do

Two of PR 133's plants in `tests/plants/sql.txt` were caught only when a live
SQL Server answered in a certain order. The new `cancel_tokens()` feeds
`tds_parse` the reply to our own cancel with no server, so both are caught
whatever the server's timing.

## Does the new case exercise the code the plants break?

Read against `src/sql/tds.c` (token(), the DONE and ERROR cases):

- Plant "firstdone" drops `st & 0x20` from the rule that ends a cancel. The
  case gives a final DONE (status 0) while `state == TDS_CANCEL` and requires
  the state to stay TDS_CANCEL. That is the plant's behaviour, not its text:
  any rule that ends a cancel on a DONE without the attention bit fails here.
- Plant "3980" changes the number of the error hidden while `quiet`. The case
  gives a well-formed ERROR token (number 3980, state 1, class 16, empty text,
  server and procedure, line 1: 14 bytes, as the length says) and then the
  DONE with the attention bit, and requires TDS_READY with nothing rendered.
  The clean run passing shows the token is read as 3980 (otherwise it would be
  rendered); the state and `quiet` are the ones `tds_cancel` sets.
