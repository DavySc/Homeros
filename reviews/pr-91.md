## Notes (non-blocking)

1. **Combined injections are gathered from the window only; Neovim reads the whole tree. Measured.** Neovim's languagetree sets `full_scan` when a query has combined injections; `inject()` runs the injection query over `s->ra..s->rz`. The comment in `syntax.c` says "as Neovim's add_injection", which holds for the keying, not for the range. `gen.py`'s `split.nix`: Lua's `x = [[` in one `# lua` string and `local y = 1 ]]` in another, 3,000 lines on. Neovim joins both and colours the second as a Lua string. Ours does so from "top, then bottom" and from a whole-file window, but colours it as code (`local` keyword, number) after "bottom only", after "top, middle, bottom", and after "top, bottom, type a space". No realistic file tried shows it (above): it needs Lua that is unbalanced inside one string and closed in another far away. The test cannot see it (texts of at most 80 lines; cases with syntax errors are allowed to differ). Ask: say so in the comment and in the test's header as a known difference; scanning the whole tree is not worth note 3's cost.
2. **Very wide nodes break the frame budget, in Nix as in Lua on main. Measured.** nixpkgs' `all-packages.nix` (10,050 lines, 303 KB, one attribute set), typing at line 6,000: frame after the parse 4.00 (3.94 to 6.28), frame before it 7.93 (7.77 to 12.58), longest stretch of `syntax_update` without asking `stop` 6.37 (6.15 to 10.30). `python-packages.nix` (23,585 lines): 16.3 and 23.1 (single run). A generated 10,000-entry table: Nix 16.3 and 32.8 (single run); the same as Lua 14.25 on this PR against 14.65 on main, before the parse 28.20 against 28.61: no measurable difference, so the cost is on main already and this PR brings a language whose largest real files have that shape. Callgrind: `ts_query_cursor__advance` 29%, `ts_tree_cursor_current_status` 14%, `ts_node_parent` 8%: tree-sitter's query cursor walking the children of one node to reach the window. **Hypothesis:** Neovim pays the same (not measured). Davy opens files this large in SQL (which does not use tree-sitter); whether he opens nixpkgs' package lists is his to say.
3. **`inject()` never asks `stop`. Measured.** A `# lua` string with an interpolation on every line makes every fragment one node of one combined region. 250 lines, typing at line 100: 41.4 (40.7 to 43.7) ms per key in one stretch. Single runs with the string's top in the window: 250 lines 98 ms, 500 lines 0.40 s, 1,000 lines 0.50 s, 2,000 lines 1.2 s, 12,000 lines 6.4 to 6.9 s per key. Callgrind: 96% under `inject` in `ts_query_cursor_next_match` (`compare_captures` 50%), not in the PR's own loops. A realistic one (600 lines of Lua with 20 interpolations) costs 0.38, the same as that Lua in a `.lua` file (0.37). Only a contrived file reaches the bad case, but when it does the editor is frozen, not slow; the parse beside it does ask `stop`.

Smaller: one `#gsub!` is kept per pattern (the last); every pattern in the Nix query has exactly one, so nothing is lost today. A stray space ends the comment line "in-progress matches. " in `tests/test_syntax.c`.
