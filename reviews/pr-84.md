## Findings, first pass (head 0c6474a): changes requested

**1. Blocking, fixed in 61fe264. A file's escape sequence reached the terminal.** The language line copied the info string's bytes into the grid with `wput`, not through `put_cell`. With the line `` ```c \x1b]0;PWNED\x07\tz `` the tty backend wrote `\x1b]0;PWNED\x07\t` raw (1 run; on main: `^[]0;PWNED^G`, 1 run). Neovim's overlay shows a control character as `^A` and a tab as blanks (`cases1.py` P5). After the fix: 4 draws of the line in the probe's output, none with a raw ESC, BEL or tab (1 run on 61fe264, 1 on be8d7af). Named case 1028 and a plant hold it.

**2. Fixed in 61fe264. An icon on the row above the line.** `over()` was called with an unset column (`(size_t)-1`) for a marker cut off below the window, which draw_line's comment called harmless. With wrap and a text width that is a power of two, `(int)(SIZE_MAX / tw)` is -1 and the icon went to the last column of the previous row: `cases3.py` R1 to R3 (box, bullet, number; widths 32 and 16) differed from Neovim, R4 (width 30) did not. After the fix all four match; cases 1029 to 1031 and a plant.

**3. Fixed in 61fe264. An ordered number wider than its marker hid the item's text.** 103 items `1. item N`: the core drew `100.tem 100`, Neovim `100.1. item 100` (inline text; `cases1.py` P2, P3). Now the marker is left as typed when the number is wider (case 1032, listed as known); `10.` over `1. ` is still an overlay (case 1033, plant on the `<=`).

Also sent: the test's header counted 25 named cases and 1025 in all where the trace had 27 and 1027 (fixed).
