## 1. The region rule

Neovim 0.12.6 `languagetree.lua`, `LanguageTree:_edit` (line 1163): edits
every tree, rebuilds `_regions` from `tree:included_ranges(true)` (the ranges
after the edit), and invalidates a region if `Range.intercepts(r,
changed_range)`, where `changed_range` is the edit's start and *old* end.
`_range.lua` line 97: not intercepting when `le(r.end, other.start)` or
`ge(r.start, other.end)`, on (row, column). The PR's

```c
hit |= !le(g->r[k].end_point, e->start_point) && !le(e->old_end_point, g->r[k].start_point);
```

is that test with `ge(a, b) == le(b, a)`, after `ts_range_edit`, with byte
columns as Neovim's, and an empty region still always hit (Neovim's
`#region == 0`). **Measured** that it matters: the old byte test is the PR's
new plant, and `edit_before_region` fails with it. **Measured** that Neovim
agrees with the test's expectation (table above).

The seed-16 case `449.md` no longer reproduces on main either (main's seed
16 also gives 0 of 900: the corpus is drawn from repo files and changed with
the latest merges), so the directed test now carries this case alone. That
is the right home for it.

## 2. PR 42's follow-ups

- **`syntax_edit` moves `ra`, `rz`.** Confirmed by the probe: the frame
  PR 42's review found (far.c 26 2240 12) differs without the line and not
  with it. `ra`/`rz` also bound which regions `parse()` reparses and where
  `inject()` looks; moving them keeps them on the same text as the regions'
  ranges, which `ts_range_edit` moves the same way, and `syntax_update`
  recomputes both from the next frame's lines anyway. No difference in
  1.44 M frames.
- **A cache miss fills `s->cap`, not 8 KB, up to `WINDOW`.** See note 2.
- **`cache_grows` and its plant.** The plant (no `s->cz = 0` after the cache
  grows) is caught at `test_syntax.c:378`, the directed check, not by chance.
- **`bench/run.sh`.** Not rerun here; the line adds `loop` and `-lm`, which
  is what `reviews/pr-42-repro/bench.sh` needed.

## Notes (non-blocking)

1. **`show()` changes what `planted.sh` prints as the reason.** On a face
   mismatch `test_syntax` now prints the case's text, which is drawn from
   repo files, so `planted.sh`'s reason grep picks the first line of that
   text that looks like a failure: "priority tie" shows `CHECK(text_lines(t)
   == lines);`, "not- predicates" shows `CHECK(!pipe(p));`, "byte after the
   edit" shows `CHECK(oil_actions(...` (**measured**). I reran those three
   with their logs kept: each fails for the right reason (face mismatches, or
   8 of 526 frames before a parse). So the plants are caught, but the line
   `planted.sh` reports is noise, and a test_syntax plant that failed for
   another reason after a mismatch printed a case would also look caught.
   Suggest for thread 0 or package 12: have `planted.sh` skip lines between
   `---- ` markers, or print the case text with a prefix its grep excludes.
2. **The `w = s->cap` fill has no check that sees it.** The probe compares a
   frame with one drawn after `s->cz = 0`, which takes the same fill path,
   so it cannot see the fill size: with the old `w = CHUNK` it gave 0 of
   108,000 differing frames (far.{c,md,lua}, seeds 1 to 6, 120 and 400
   rows, **measured**). The change follows PR 42's stated intent and costs
   nothing, but it belongs in `tests/plants/syntax.txt`'s "Not planted" list
   as (5), like the `ra`/`rz` move.
3. CI on the head was running when this was written; merge waits on it.
