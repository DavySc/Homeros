## What changed

1. `git_attach` sweeps deleted buffers only once git has the editor
   (`git_ed()`, set by `git_key` on every key). Before that `git_buf()`
   knows no buffer, so attaching the second file of `homeros a b` dropped
   the first. Skipping the sweep is safe because the core never reuses a
   buffer number (`b->nr = ++top_file_num`, core.c), so a stale entry can
   only be found by a deleted buffer's number; it leaks until the first key.
2. test_git_signs: the never-attached check now uses a buffer of a second
   repository, and checks that repository is not looked for, so it still
   holds once the core attaches every file it reads (the old `!git_repos`
   would not).
3. win.c: the batch reader moves out of `git_drain` into `git_batch`, and
   test_git_win checks it on a hand-built Wine-style batch (second entry at
   offset 30, not DWORD-aligned) instead of hoping Wine batches four writes
   together (two CI misses).
