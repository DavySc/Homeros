# GUI backend measurements, 2026-11-17

Same job in both: a 1600x1000 window, 60 lines of proto/c/pt.c in JetBrains Mono, typing appends to line 0, redraw only on events.
Compositor: weston 16 headless (pixman), the sandbox has no GPU. Davy's machine: Hyprland on Wayland, NVIDIA.
Typing: 200 characters injected at 10 ms (SDL: SDL_PushEvent from a thread; Wayland: a timerfd in the poll loop).

| | SDL3 3.4 + SDL3_ttf (sdl3-ed.c) | Raw Wayland + FreeType + xkbcommon (wayland-ed.c) |
| --- | --- | --- |
| Our code | 48 lines | 109 lines (+ generated xdg-shell glue) |
| Our binary | 17 KB | 37 KB |
| Shared libraries pulled in | SDL3 4.8 MB, SDL3_ttf 0.2 MB, HarfBuzz 1.8 MB, FreeType 1.0 MB, plus Mesa | libwayland-client, xkbcommon, FreeType 1.0 MB |
| First frame after start (3 runs) | 458 (cold), 74, 82 ms | 5.6, 5.4, 5.0 ms |
| Full redraw, mean | 3.05 to 3.31 ms (llvmpipe GL) | 0.66 to 0.89 ms (CPU into shm, whole window) |
| Threads | 11 (cursor, 4 llvmpipe, SDL workers) | 1 |
| Wake-ups in 20 s idle | 7 on the main thread | 0 |
| RSS | 137 MB (mostly llvmpipe) | 11.7 MB |

Facts found on the way:
- SDL3 on Wayland has no software framebuffer ("Window framebuffer support not available"); it needs EGL or Vulkan, so a GPU driver (and its threads and memory) is always loaded.
- SDL3 loads libdecor's GTK plugin for window decorations; under a seatless compositor it crashed in GDK until LIBDECOR_PLUGIN_DIR pointed nowhere.
- Correction after review 2: the 121 frames for 200 keys are weston-pixman's doing (it holds a buffer until the next repaint), not the client's. On weston's GL renderer the same client drew 1,950 frames for 2,000 keys, and on pixman key-to-commit p99 was 16.6 ms. The design draws on frame callbacks instead (specs/Present.tla). First frame here means commit queued; weston showed it at 18.0 and 22.6 ms.

Not measured here (hypotheses until phase 0 on Davy's machines): NVIDIA GL numbers; Windows (Win32 + FreeType into a DIB section is the planned twin of the Wayland backend); IME (text-input-v3 / IMM32), clipboard, fractional scaling, client-side key repeat, cursor shapes, CSD under GNOME.

## How to run

`run.sh` (from the review) has the full sequence: build `env.nix`, start `weston --backend=headless --socket=wl-test --renderer=pixman` (or `--renderer=gl`), and for SDL3 and the GL renderer point `LD_LIBRARY_PATH`, `__EGL_VENDOR_LIBRARY_FILENAMES` (or `_DIRS`) and `LIBGL_DRIVERS_PATH` at the env's lib, glvnd and dri directories, set `LIBDECOR_PLUGIN_DIR` to a missing directory, and run each binary with `INJECT=1` for the 200-key test. Compile: `gcc -O2 sdl3-ed.c $(pkg-config --cflags --libs sdl3 sdl3-ttf)`; `wayland-scanner client-header/private-code xdg-shell.xml` then `gcc -O2 wayland-ed.c xdg-shell.c $(pkg-config --cflags --libs wayland-client xkbcommon freetype2)`.
