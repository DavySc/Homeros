# Review of PR 96: Windows checks pass only when the test's summary is its last line

Reviewer: separate review thread, 2026-11-20/21.

**Verdict: APPROVED at 221b08c** (second pass, see the end). First pass at 6315d9c:

## First pass (6315d9c merged with main 8c1d49c, merge f34e08a)

The idea is right and the author's claims hold, but piping the test into `tee` makes a
failing test that leaves a child process alive hang the check forever. One of the 90
existing Windows plants does exactly that. The fix is a three-line change to
`tools/winpass.sh`.

## Findings

### 1. Blocking: the pipe hangs the check when a failing test leaves a child alive (measured)

`pass` runs `timeout ... "$exe" 2>&1 | tee file`. A child the test started inherits the
pipe; when the test dies on a failed CHECK, the child lives on and `tee` never sees the
end of its input. `timeout` has already returned, so nothing ever ends the wait.

- Plant "win: journal without the lock" (`make win WIN=file`, tests/plants/file.txt):
  `tests/test_file_win.c:361: CHECK(journal_open(...) == -1 && errno == EWOULDBLOCK) failed`,
  then `test_file_win.exe holder` stays alive.
- In the full plant run the shard sat on this plant for 104 minutes until I killed the
  holder (1 run). Repeated alone: PR's script still running when my outer limit killed
  it at 420 s (1 run); main's script on the same plant printed `FAIL test_file_win` and
  returned in 40 s (1 run).
- In CI this is a plant shard that times out at 90 minutes: red, but for the wrong
  reason and at the cost of the whole shard. The author's rerun of the 90 Windows plants
  would stop here too.

Fix tried (`pr-96-repro/winpass-file.diff`): write the output to the file, then `cat` it,
and take `timeout`'s status directly. With the plant: `FAIL test_file_win` after 37 s
(1 run). Without: `make win` passed (271 s, 1 run), `src/undo/win.sh` passed. It is also
shorter (no `PIPESTATUS`). The only loss is live output while a test runs.

### 2. Small: test_win's own crash line passes for its summary (measured, status loss simulated)

`tests/test_win.c:117` prints `test_win: FAIL, exception 0x...` from its exception
handler and calls `ExitProcess(3)`. That line starts with the test's name and a colon,
so `pass` accepts it as the summary; the comment in winpass.sh says no earlier line does.

- Trap planted at the start of `main` and the handler's `ExitProcess(3)` changed to
  `ExitProcess(0)` (standing in for a lost status): `make win WIN=win` passed, 2 of 2.
- How likely the loss is: the same trap with the real handler gave status 3 in 20 of 20
  raw runs under Wine, so I did not see Wine lose a status set by `ExitProcess`.
  Hypothesis: only an unhandled trap loses it. The risk is small, the fix is one word
  (for example `test_win FAIL: exception ...`).
- A trap after the "(measured)" line is caught anyway, by accident: stdout is flushed at
  exit, after the handler's stderr line, so the last line is the measured one (6 of 6).

`pr-96-repro/fool.sh` feeds `pass` 12 fake outputs; it is fooled only by a line that
starts with the test's name and colon before the summary (the case above). A CHECK
failure line, a "(measured)" line, no output, another test's summary, a line after the
summary and a hang after the summary all fail, as they should.

## Every Windows check goes through the helper

Checked by grep for `wine` and `.exe` over the Makefile, `*.mk`, `*.sh`, `*.py` and the
workflows. The eight scripts that run a Windows test (`src/{file,git,kitten,loop,shada,
tools,win}/check.sh`, `src/undo/win.sh` through `src/undo/build.mk`) all call `pass`,
ten call sites, none left on a bare exit status. CI's `windows` job runs
`src/git/check.sh` natively and so uses it too (RUNNER empty). The remaining `wine`
calls are in `reviews/*-repro/`, not checks. All nine tests print a summary that starts
with the test's name and a colon as their last statement before `return 0`; a failed
CHECK prints `tests/test_x.c:N: ...`, which does not match.

Limit by design, not a finding: a crash after the summary with status 0 passes. Nothing
but `return 0` follows the summary in any of the nine tests.

## Duplication and size

No copied logic: the rule lives once in `tools/winpass.sh` (13 lines). Optional
shortening: the ten call sites all end `|| { echo "FAIL ..."; exit 1; }`; `pass` could
print `FAIL <name>` itself (planted.sh needs the word FAIL). Not required.

No plant covers a script going back to a bare `timeout wine` (the new plant covers the
helper through the loop check only). Acceptable; one plant per script would be eight
near-copies.
