## Findings

### 1. One line of the fold changes behaviour, the PR says it does not, and nothing tests it (changes requested)

`setsize()`: `full = a == ROWS ? e->cols : e->layout->size[ROWS]`. Main's `setwidth()` compared the frame's height with `e->rows`. The PR body: "The result is the same either way."

It is not, once the terminal has shrunk below what the windows need (the top frame is then taller than the terminal):

- **measured**: 14 of 120,000 random sequences end differently on main and on 3b1cb70; each has a resize to a smaller terminal before a width change (CTRL-W `>`, `|`, or entering a window narrower than 'winwidth'). `reduce.py` cut them to 6 to 9 commands each.
- **measured** in real Neovim (tmux, `bent.sh`, 1 run): 12x40, `:3vs`, `:3sp`, `:10vs`, `:new`, terminal to 4x15, `17 CTRL-W >`. Neovim's widths before the last command: 11, 3, 1, 1, 1; after: **1, 13, 1, 11, 11**. The PR gives 1, 13, 1, 11, 11. Main gives 11, 3, 1, 1, 1 (nothing moves).
- So the new comparison is the right one here: Neovim keeps `Rows` at what the windows need (it reported `lines` 7 in a 4-line terminal), so its ROWS_AVAIL is the bent top frame's height, which is what the PR compares with (**hypothesis** beyond this one measured case; the reading of `frame_setwidth()` agrees).
- **measured**: with the line put back to `e->rows`, `make test TESTS="core_screens core_contract"` passes (plant x1 in `extra-plants.txt`, not caught). The recorder cannot reach this state: `:set lines` below the minimum fails with E593 and the case becomes a nop.

Asked for: (a) the PR body's sentence corrected to say this is a fix and where it shows; (b) a case in `tests/test_core_contract.c` with the measured numbers above (a `grid_resize` to 4x15 after the four splits, then `core_resize(&e, 1, 17, 0)`, widths 1, 13, 1, 11, 11); (c) its plant (x1's line). About 12 lines.
