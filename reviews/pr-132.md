## Findings

### 1. The properties accept a frame that redraws for ever (to fix here)

Fresh and NoWaste say nothing about an idle editor. Two mechanisms pass both and draw at the refresh rate until the editor exits (**measured**, 2 runs each):

| Mechanism | PR's properties | With NoIdle added |
|---|---|---|
| "keep": Draw does not clear the frame's dirty flag | pass (`FramesX_keep_pronly`, 360 states; also planted in the PR's own file, 260 and 17,576 states) | fail (`FramesX_keep`) |
| "sharedall": one dirty flag, cleared once every frame has drawn its last edit. This is the obvious repair of the rejected "shared" | pass (`FramesX_sharedall_pronly`, 492 states) | fail (`FramesX_sharedall`) |

"sharedall" is the dangerous one: with one frame on a hidden workspace the flag never clears, so the visible frames are drawn 60 to 144 times a second while nothing changes. That is Davy's normal use (several workspaces), and against the top rule ("no clock cycle is ever wasted"). Kitten.tla already states the same kind of property ("an idle editor is never woken by it").

Asked: add the property and one broken variant that fails it. `FramesX.tla` has a version that works: a flag per frame set by an edit that touches it, and `NoIdle == ~idle` where Draw sets `idle` when no edit touched the frame since its last draw. `ok` passes it (200 states, as before).

CLAUDE.md: "Every check has a plant in `tests/plants/` ... a new check adds one." Save2, Kitten and Pace each have a `specs:` line; Frames has none. This line works (**measured**, 1 run, through `make -s specs` in a copy):

### 3. "all" is rejected only because a frame is hidden (suggested)

With all three frames visible, "all" passes both properties (**measured**, 2 runs, 3,676 states; `FramesOwn_all_pronly`). The model has no time, so it cannot see that waiting for every callback holds a 144 Hz frame to a 60 Hz monitor's pace, which is the case `frames-os.md` finding 5 is about. One line without time catches it: `Own == \A f \in Frames : dirty[f] /\ ~cb[f] => ENABLED Draw(f)` (a frame that is dirty and has its callback may draw whatever the others do). "all" fails it, `ok` passes with 8,000 states (**measured**, 2 runs each, `FramesOwn.tla`).

### 4. Hiding and showing a frame while the editor runs is not in the model (suggested)

`Visible` is a constant. A workspace switch on Hyprland changes it mid-run. I added up to 3 flips and asked Fresh of every frame that ends visible: `ok` passes with 2 frames (2,400 states) and with 3 frames and 2 flips (48,000 states), NoWaste and NoIdle included (**measured**, 2 runs each, `FramesX_flip`, `FramesX_flip3`). So the mechanism holds; either add the config or say in the row that visibility is fixed per run.

### 5. Which frame a key acts on has no model, and the header request's rule has a counterexample (not this PR; before main.c and the backends)

Frames.tla covers drawing only. The input side is also an ordering question (the compositor moves the focus some time after the editor asks, or never), and CLAUDE.md asks for a model for those. `Focus.tla` states one property, InFrame: every key acts on the frame the user's own commands chose before it (type-ahead after `SPC 5 o` goes to the new frame). Three rules for the loop, 3 frames (**measured**, 2 runs each):

| Rule | Result |
|---|---|
| "enter", as `frames/header-request.md` reads: `SPC 5 o` enters the tab page at once and raises; KEY_FOCUS enters its tab page | fails with 2 switches and a key: the focus event that answers the first raise arrives after the second `SPC 5 o` ran and pulls the current frame back, so the key lands in frame 2, not 3. Passes with one switch and a key |
| "follow": a key acts on the frame of the window it arrived in (`input()`'s `win[i]`) | fails with one switch and one key (the key reaches the old window before the compositor moves the focus) |
| "wait": `SPC 5 o` only raises, the focus event enters | fails the same way |
| "count": "enter", but drop a focus event that answers the editor's own raise | passes (4 actions, 367 states). A sketch only: it miscounts when the compositor refuses a raise (Hyprland without the rule) |

How often the "enter" trace happens is a **hypothesis**: it needs the second `SPC 5 o` typed before the first raise's answer arrives, so a busy editor or very fast keys. "follow" and "wait" fail on plain type-ahead, and the header text does not rule them out. Asked of the frames thread and thread 0: state the rule and model it before `main.c` and the backends build on it. Mouse clicks and a refused raise are not in my model.

### 6. The `SPC 5 m` row leaves out the tools that already do this (minor)

"No reference editor to compare against" holds for the editors DESIGN.md names, but tmux's `join-pane -t` moves a pane into an existing window, and kitty's `detach_window` moves a window into another tab (**hypothesis**: from memory, not run here). They answer two things the row leaves open: where the window lands in the target frame's layout, and whether the focus follows. Worth a line in the alternatives and a choice in the scenarios.

## Attacks that found nothing

- **Per-monitor pacing on Wayland.** Each frame's Repaint is its own action under weak fairness, so any mix of rates is covered (**proved** within the bounds, the `ok` configs).
- **Key release in another frame.** Today's backends already ignore it: `src/wl/wl.c` uses a release only to stop repeat for the repeating key, and `kb_leave` stops repeat; `src/win/backend.c` handles no `WM_KEYUP` at all (**read**, not run: there is no second window to run it in yet). It needs a backend test with the wl and win packages, not a model.
- **Hidden workspace callbacks.** Covered by `Visible` and by finding 4's runs.

## Notes for later PRs

- **Windows pacing with several frames** is outside Frames.tla (its Repaint stands for a frame callback) and outside Pace.tla (one window, one timer). `frames-os.md` calls "the same model per frame" a hypothesis. Package 9's PR should model N frames on the one waitable timer. Not run here.
