## What the PR does

- `fold_closed()` returns the closed fold's level instead of 1: `lvl + 1`,
  which is `fi_level` as `hasFoldingWin()` sets it for a closed fold. The
  oracle records it with `foldtext=v:foldlevel` and `foldtextresult()`.
- `fold_cmd()` returns 1 when it changed a fold (Neovim's `DONE_ACTION`,
  after which `setManualFoldWin()` calls `changed_window_setting()`), 0 when
  it found a fold and changed nothing, -1 for E490. zO joins zo and zc in
  the `setFoldRepeat()` loop. The 'foldlevel' commands always return 1, as
  `newFoldLevelWin()` always calls `changed_window_setting()`.
- `fold.h`'s two comments (thread 0's wording) say the above.
- It carries the report commits of PR 117's review.

## Findings

1. **Nothing checked the answer 0 (fixed in d611295).** At e4b77a3 the trace
   compares only E490 and the fuzzer only "an answer other than 1 means
   nothing differs". A `fold_cmd` that answers 1 whenever it finds a fold
   passed everything: `return n || done ? 1 : -1;`, zv's `return 1;`, and zO
   answering 1 always. The core would then redo the view on every zo on an
   open fold. Asked: after a command with a count, the fuzzer runs zO or zv
   once more and it must not answer 1 (`fuzz-zero.diff`), with a plant. The
   count matters: with count 0 the first zO does nothing. Applied as given.
2. **A plant no longer applied (fixed in f17de10).** "zv opens one fold
   only" named `while (...) {}`, which a6f093e8 rewrote; `planted.sh` said
   BROKEN PLANT, which would have turned the train red. The replacement
   (`if` for `while` on the new line) is caught by the trace.

## Notes

- zO with a count: Neovim's `opFoldRange()` runs once whatever the count;
  here the loop's second round finds nothing closed and leaves. Same folds
  (the trace has zO with counts 1 to 3). With count 0 zO now does nothing,
  as zo and zc; Neovim never passes 0 (`count1`).
- 1 does not promise a visible change (a one-line fold that shows open
  either way, as in Neovim); 0 and -1 do promise none, and that is what the
  fuzzer holds.
- The first make check and plant runs of this review were lost to a restart
  of the review machine; the results above are from the runs after it.
