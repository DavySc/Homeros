# Review of PR 169: a connection's password may hold spaces (package 22)

Head reviewed: 32cbff8a (one commit on PR 168's 16d2538c). Reviewer thread
"Review SQL password spaces PR 169", 2026-11-27.

**Verdict: APPROVED** at 32cbff8a. One should-fix in Davy's docs (finding 1),

## What changed

`lookup()` in `src/sql/sql.c` now finds the first `pass=` that follows a
space or tab, cuts the line there, strips CR/LF and takes the rest of the
line as the password; the six words before it are read as before (`trust`
must be the sixth). README says `pass=` comes last. One test line
(`sp ... trust pass=Ho meros 1 x\r\n`, login `hsp` created with that
password) and two plants.

## Findings

1. **Should-fix (docs, Davy-facing): `pass=` before `trust` now breaks.**
   The base accepted the two optional words in either order, and the
   Windows trial README (`/mnt/project-files/homeros-windows/README.md`,
   "then optional words") gives no order. On the PR,
   `pass=secret trust` makes the password `secret trust` and drops trust:
   F5 shows "TLS: certificate verify failed", which does not point at the
   cause (measured above). This is inherent to "rest of the line" (a
   password may end in ` trust`), so the code is right; the next Windows
   build's README must say `pass=` comes last, and Davy should move it last
   in his file. Not blocking.
2. **Owed tests (next package 22 PR).** My plants: 5 of 9 caught, plus 0 of
   2 in a corrected second set. Not caught:
   - a tab before `pass=` not recognised (`pw[-1] != ' '`);
   - `pass=` inside a word taken (`bypass=`), and the last `pass=` taken
     instead of the first (password containing ` pass=`);
   - `trust` always on: no test refuses a self-signed certificate for a
     line without `trust`, though this PR rewrote how `trust` is read;
   - trailing spaces trimmed from the password (5 of 5 direct runs not
     caught; two earlier "caught" results were stale objects in prun's
     same-second mtime cache, hypothesis). SQL Server compares exactly:
     sqlcmd with `trail` fails, `trail  ` logs in (measured).
   - `*pw = 0` removed: equivalent unless a line has fewer than six words.
3. Notes, not blocking: trailing spaces are part of the password (libpq's
   pgpass does the same), so a stray trailing space gives "Login failed";
   a UTF-8 BOM hides the file's first line (pre-existing; Notepad's "UTF-8
   with BOM"); the empty `pass=` message says "has no pass="; passwords are
   still cut at 255 bytes silently (pre-existing).
