## First pass: 4edc86f0

## Blocking findings (each **measured**, deterministic, 1 run unless said)

1. **Editing the buffer while a script runs sends SQL that is in no version of the buffer.** `next()` reads each batch from the live text at the offsets `sql_split` found at F5. `p1b`: batch 1 is `waitfor delay '00:00:01'`, batch 2 ends in `where id = 1042`; two spaces typed in batch 2 while batch 1 waits, and the server gets `where id = 104` (0 rows instead of 1). With a `delete` that is the wrong rows gone. `p1`: a line typed at the top gives "Incorrect syntax near 'go'". Wiping the query buffer mid-run prints "sql: out of memory" (`p5 2`). SSMS runs the text as it was at F5. Wanted: the run owns its text from F5 on (one copy of [a, z), batches as offsets into it), with a test that edits mid-run and a plant.

2. **F5 while a cancel is still being acknowledged empties the results, runs nothing, says nothing, and drops the connection.** `p2b ms 0|5|20|50` and `p2b pg 0`: Alt+Break, then F5 0 to 500 ms later: the results are one blank line; the temp table made before is gone at the next F5 ("Invalid object name '#t'"), so an open transaction would be rolled back too. Cause: Break sets `q.n = 0` at once, `run()` then takes the session as idle, `db_query` refuses (state CANCEL), and `next()` prints the empty error and calls `drop()`. Cancel, fix, F5 inside half a second is the normal rhythm. Wanted: the session is busy until the server has answered the cancel (F5 then says so, or waits and runs); a test and a plant.

3. **No room for the split leaves the session stuck.** `p5 3`: with 11 windows F5 gives E36, and from then on every F5 says "a query is running (Alt+Break cancels)" though nothing runs, also after `:only`. `run()` returns with `q.n` set when `show()` fails.

4. **The run's state machine has no model and almost no tests.** F5, Alt+Break, the wake, the batches, the cancel connection and the drop are a timing question (CLAUDE.md: a TLA+ model with the property first and a broken variant); findings 1 to 3 are all in it. Of 20 bugs I planted in `sql.c`, the editor test caught 4 (`plants.py`; uncaught: the results window not following the tail, login messages shown, the last `dir` line winning, `/a/ms` holding `/a/msx`, Break during login, the Postgres cancel connection unwatched, a `v` selection's start, a second F5 during a run, batches after a cancelled one still running, the Postgres default port, the cursor after SPC r from the results, `~` in a `dir` line (2), a dead connection kept, the results left modifiable, F5 in Insert mode). The 7 plants the author added at 4edc86f0 cover other lines. Wanted: the model (properties at least: a batch's text is the text at F5; no query is sent unless the session is ready; a run always ends; a cancelled run sends no further batch), and a test with a plant for each rule above.

5. **Three mechanisms are written a second time** (Davy, 2026-11-21: one way to do one thing):
   - `put()` is `make.c`'s `put()` (append at the end, windows on the last line follow), as its own comment says; `shown()` is `make.c`'s too. One function in the core, through thread 0, that both call.
   - Emptying the results and resetting its windows (`run()`, two lines) is `core_buf_fill(E, r, "", 0, 0)`.
   - The Visual area's byte range is computed in `snip.c:539` already, there with the last character whole. The copy here adds one byte, so **a `v` selection ending on a multi-byte character sends half of it** (`p4`: `select N'café` selected to the é reaches the server as `caf` + U+FFFD). One function for both, through thread 0.

## Notes (not blocking)

- **For Davy to decide:** there is one results split for all query buffers, so F5 in a second `.sql` window closes the first one's results (`p5 4`). The PR says "as SSMS has one per query window", but SSMS keeps one for each query window. With queries side by side on three monitors he may want each query to keep its own.
- F5 does nothing in Insert mode and from the results window (`p4`, `pty1.py`); SSMS runs from both. In a terminal there is no cancel key at all (no terminal sends Break), and many laptop keyboards have no Break key: Ctrl-C while a run is on would be a second way that works everywhere.
- Columns are separated by tabs and do not line up; the results window is titled "[No Name]".
- `Spec.pass` stays in memory for the editor's life (for reconnects) and `lookup()`'s stack copies are not wiped, while PR 133 wipes the clients' copies. Decide which rule holds.
- A wiped buffer's connection stays open (`p5 1`: 2 sessions left on the server); nothing closes a session before exit.
- The connection is looked up once per buffer: a changed connections file needs `:Connect`.
