# Review of PR 82: wl, a ligature coloured per cell under the cursor

Reviewed 2026-11-19 at head edc1688, which sits directly on main 93b3e3b (the merge is a
fast-forward, so the head is the PR merged with main). Contract: `include/backend.h`,
`src/wl/README.md`. Repro files: `reviews/pr-82-repro/`.

**Verdict: approved.** The change does what PR 68's finding 3 asked. Two follow-ups for
package 8, neither blocking: a neighbouring case that was already wrong on main (finding 1) and
a test that does not cover the new lines (finding 2).

## What was run

- **measured** (`cur.c`, 1 run on the head, 1 run with main's `wl.c` as the control): 11 words
  (`a->b`, `x /\ y`, `a-->b`, `a!=b`, `a===b`, `a<=>b`, `x↔y`, `⟹  b`, and three with a face
  per cell), the cursor on no cell and then on each cell. Per cell the probe counts the pixels
  that are not the cell's background; reversing a cell only swaps two colours, so the count must
  not depend on where the cursor is.
  - Head: every cell of every ligature keeps its count at every cursor position (`-` of `->`:
    18 pixels, #262637 on the #cdd6f4 cursor), and with faces each part takes the colours of
    the cell beneath it (the cursor reverses that cell's own face). The only 2 failures are
    finding 1.
  - Control (main): 26 failures. Main had two forms of the bug: the cursor on `-` shows a bare
    block (18 pixels to 0), and the cursor on `>` makes the `-` disappear (18 to 0). Both are
    fixed.
  - The cursor walked across each word one cell at a time, the old frame in every buffer:
    0 of 49 steps differ from a whole redraw (`span` widens to the word, so the whole ligature
    is redrawn when the cursor enters or leaves any of its cells).
- **measured** (`reviews/pr-68-repro/cost.c`, -O2, 36x128 cells, 100 presents a run, 5
  alternating runs a side): rows with no blank, main median of medians 1,621 us (1,440 to
  2,063), head 1,789 us (1,428 to 2,199); rows of 8-letter words, main 1,374 us (1,210 to
  1,995), head 1,588 us (1,287 to 1,728). Inside the run-to-run spread: no measurable
  difference.
- **measured** (`reviews/pr-68-repro/bear.c` at 16, 20, 24 and 32 px): no ASCII glyph starts
  left of its cell, so in code the per-cell colouring touches only ligatures and the 214 to 218
  symbols that reach back (↔ takes 2 to 6 pixel columns in the colour of the character before
  it in the same word, as kitty's per-cell sprites do).
- Read: the loop ends (`m > j0` always), `gx + j0 >= 0` (from `ax`), no allocation, one more
  `colours()` call per earlier cell a glyph covers.

## Findings

1. **Follow-up, already on main: a wide symbol's spill vanishes at the cursor.** `⟹` spills 57
   pixels into the blank after it. With the cursor on the `⟹` the spill is drawn in the
   reversed foreground on the blank's plain background: 0 pixels left, half the arrow is gone.
   With the cursor on that blank the spill is drawn in the text colour on the cursor: 0 pixels.
   **measured**, same on main and on the head (`cur.c`, the two lines marked `!`). The PR keeps
   the part right of the glyph's cell in the glyph's own colours on purpose (README); the fix
   belongs with the same loop. **hypothesis** (from memory of kitty's `fonts.c`, not checked
   here): kitty gives the space cell the symbol's foreground but keeps the cell's own
   background and cursor.
2. **Follow-up: the new test does not cover the new lines.** It checks one thing: the cursor on
   the first cell of a two-cell ligature is not a bare block. Four bugs planted in the two new
   lines (`mutants.txt`) all pass `make test TESTS=wl` (**measured**, 1 run each) and all fail
   `cur.c`: the whole glyph in its first cell's colours; a three-cell ligature coloured from the
   wrong cell; a part ending half a cell late; only the cursor's own cell coloured per cell
   (which is main's second bug form: the cursor on `>` hides the `-`). A test that would catch
   all four: on `-->`, the cursor on each cell in turn, each cell's count of pixels that are not
   its background equal to the count with no cursor.
3. **Note:** `reviews/pr-68-repro/lig.c`, shipped again with this PR's report commit, no longer
   compiles on main (`grid_puts` gained arguments); `cost.c` does. `cur.c` covers its cursor
   part.
