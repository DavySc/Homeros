# Review of PR 60: T-SQL formatting, SQLDiff's `sqldiff fmt` native

Reviewer: a separate Fable 5.2 thread, 2026-11-18. Reviewed at 81ef5d9, re-read at 7170e03 (that commit only moves the header to `include/` and names module 18 in CLAUDE.md; `sqlfmt.c` is byte-identical). Base: PR 58's branch at 6d72f8c. Reference: DavySc/SQLDiff `main` at 1c4adab, `cargo build --release -p sqldiff-cli`, run as `sqldiff fmt -d tsql --keyword-case lower`.

## Verdict: changes requested

The port is faithful. On every well-formed input I tried it prints what `sqldiff fmt` prints, and it is roughly 100 to 600 times faster. Three things block the merge: code that repeats package 12's (Davy's rule), a hard limit that silently changes the layout of large statements, and checks that miss most planted bugs because the comparison with sqldiff is not in `make check`.

## Blocking

### 1. The word lookup and two helpers repeat `src/syntax/tsql.c`

Davy, 2026-11-18: no duplicate parser implementations, as little duplication as possible. The lexer is shared (`tsql_token`, no second tokenizer: holds). These are not:

- `lookup()` (sqlfmt.c:93) is `tsql_word()` (tsql.c:117) again: copy lower-cased into a buffer, binary search a sorted table of words. `wname[]` is a second sorted word table; 94 of its 102 words are already in `tsql_words.h` (**measured**: script in the session, the 8 missing are `dialog limit materialized natural offset returning temp temporary`). Every word token is searched twice, once in each table (`lex()` and `keywords()`).
- `is_space()` (sqlfmt.c:115) is tsql.c:37 character for character.
- `closed()` (sqlfmt.c:119) walks every string, quoted name and block comment a second time to learn what `tsql_token` knew when it returned: whether it stopped at the closer or at the end of the text.

Fix, through package 12 and thread 0 (tsql.h is going to `include/`): one lookup that returns the word's index or a class-and-id pair, with the formatter's `W_*` values taken from that table; `tsql_token` reporting an unclosed token (a kind bit or a flag in `TsqlRd`); `is_space` exported or the gap test written with `tsql_token` itself. That removes about 45 lines here (my estimate: `wname`, `lookup`, `is_space`, `closed`).

### 2. A statement of more than 65,536 tokens loses its clause breaks

`clauses()` (sqlfmt.c:626) collects a statement's significant tokens into `static int sig_[1 << 16]` and returns without setting a break when the statement has more. SQLDiff has no such limit.

**Measured** (1 run each, deterministic):

| input | Homeros | sqldiff |
|---|---|---|
| `SELECT a,a,...,a FROM t`, 65,536 tokens | same as sqldiff | `from` on its own line |
| the same, 65,538 tokens | `from` stays on the `select` line | `from` on its own line |
| `INSERT INTO dbo.t (...) VALUES` + 9,000 rows, 303 KB (`gen.py`, `bigvalues.sql`) | `values` stays on the `insert` line | `values` on its own line |

A data script with a multi-row `VALUES` reaches this at about 300 KB, and Davy opens SQL files over 600 KB. Nothing reports it: `sqlfmt` returns 0. The array is also 256 KB of the binary's memory for one call. No test or plant reaches the limit (plant "clause breaks stop after 4096 tokens" is not caught, below). Fix: no cap. The loop needs only the previous and the next significant token, so it can walk the events without the array.

### 3. The checks in the repo miss most planted bugs; the sqldiff comparison is not one of them

CLAUDE.md: a check never seen to fail proves nothing. The PR's 19 plants are caught (below). I planted 16 more (`reviews/pr-60-repro/extra-plants.txt`, run by `extra-plants.sh` against `test_sqlfmt` and 20 s of `fuzz_sqlfmt` under ASan and UBSan, no length limit). **Measured**: 5 caught, 11 not caught (`extra-plants.log`):

| plant | test + fuzz | sqldiff comparison (300 `tsql.py` + 300 `soup.py` seeds) |
|---|---|---|
| the gap around a byte the lexer does not know is laid out | not caught | not caught |
| clause breaks stop after 4,096 tokens | not caught | not caught |
| nesting limit 10 instead of 1,000 | not caught | not caught |
| `GO` before a `--` comment is a word | not caught | caught (2 texts) |
| an unclosed block comment is no parse problem | not caught | not caught |
| a label's name is recased | not caught | caught (23) |
| a sqlcmd statement ignores line breaks | not caught | caught (2) |
| more than two blank lines kept after `GO` | not caught | caught (25) |
| a doubled quote closes a string | not caught | not caught |
| `ELSE` ends no IF branch | not caught | caught (7) |
| the edit is not shrunk at its end | not caught | not caught (the edit is still right, only larger: sqlfmt.h promises no smallest edit, so either promise it and test it, or this is not a bug) |

Why: `fuzz_sqlfmt` and the random part of `test_sqlfmt` compare input and output with spaces and case removed, and that holds for any layout. Only the 17 directed cases pin the layout. The evidence the PR rests on (186 files, 4,200 generated texts) comes from `oracle/compare.sh`, which needs a Rust build and runs in no check, so a later change to `sqlfmt.c` or to SQLDiff can break the match unseen.

Fix: record the comparison as the Neovim traces are recorded: sqldiff's outputs for a few hundred generated texts plus directed cases for each row above, in a file `make test` replays (`cases.py` already records). Add generator cases for the rows the generators do not reach (unclosed block comment, doubled quotes in strings and names, unknown bytes, deep nesting, a statement over the old limit), and a plant for each.

## Not blocking, to fix or answer

4. **A NUL byte is lexed as an operator.** `strchr("+-*/<>=~!@#%^&|`?:{}", s[0])` (sqlfmt.c:184) finds the terminator when `s[0]` is 0. **Measured**: `SELECT 1\0SELECT 2\n` is formatted (`select 1\0\nselect 2`); sqldiff reports the byte and keeps the statement as written. `tests/fuzz_sqlfmt.c` already guards its own `strchr` against this.
5. **Out of memory inside the check returns a statement count, not -1.** `verify()` returns -1 both for "cannot be pinned" and for `oom`. **Measured** (`oom.c`, each of the 614 allocations of one call on sp_WhoIsActive.sql failed in turn, a fresh process each, ASan): no crash, the next call always gives the right result, 607 return -1, 7 (allocations 328 to 334) return 8 with an empty edit. sqlfmt.h says -1.
6. **Comment runs cost the square.** `indent_of()` scans from each comment to the next token. **Measured**, 5 runs each: 5,000 `--` lines in a row 4.8 ms (4.7 to 5.3), 20,000 lines 75.6 ms (74.3 to 86.0); 4 times the input, 16 times the time. sqldiff takes 0.11 s at 20,000. One indent per run of comments fixes it.
7. **11.8 MB stays allocated after one format of a 585 KB file** (**measured**, `mem.c`, mallinfo2 before and after one call on MaintenanceSolution.sql). The editor with T-SQL colours holds 2.0 MB (PR 58's review). Two token arrays of 24 bytes a token, the events, the copy of the text and the output are kept for the next call. Only `*res` has to live on; freeing the rest costs nothing measurable next to the 11 ms. PR 51 was closed with 29.5 MB as one of its costs, so this deserves a decision rather than a default.
8. **The file's opening comment says what the code does not do.** Lines 14 to 17 say the output "is lexed and parsed again and must give the same tokens, the same tree and the same parse problems". `verify()` checks tokens only, and its own comment says steps 2 and 3 are left out.
9. **Known differences are not all listed.** The PR names two. **Measured** on 4,000 random pieces of real T-SQL (below), all on malformed text, all with Homeros changing less or the same:
   - a stray `]` (Homeros keeps the statement, sqldiff formats it);
   - a bare `@` before `=` (`@=`: Homeros writes `@ =`, sqldiff `@=`);
   - `}<` and `<?` next to each other (gap kept or added);
   - bytes that are not UTF-8 (sqldiff refuses the file, Homeros formats around them);
   - a lone CR after a `--` comment (Homeros ends the comment there, as SQL Server does, and writes LF).
10. **The Windows build does not compile the formatter.** `WIN_SRCS` takes `BASE` modules only (thread 0's Makefile). Davy writes T-SQL on his Windows laptop, so the wiring PR must add `sqlfmt` and `syntax/tsql.c` there.
11. **Nothing records which SQLDiff the port matches.** Put the commit (1c4adab here) next to the recorded outputs, so drift from SQLDiff's `main` shows as a diff of that file.
12. The output is copied into a new `Text` for each check round only because `tsql_token` reads from a `Text` (0.4 ms of 11 at 585 KB, **measured**, `mem.c`, 5 runs). The text itself is read twice for the same reason (once into `src`, once through `TsqlRd`). A reader over flat bytes in tsql.h would drop both; for package 12 and thread 0 with finding 1.
13. `sqlfmt.c` is linked into the editor and nothing calls it until package 5's wiring. Accepted for a stacked PR; say so in the PR.

## What holds

- **No second tokenizer**: every token comes from `tsql_token`; the recasable words come from `tsql_word`'s `TQ_RECASE` class.
- **Same output as sqldiff on real T-SQL** (**measured**, 1 run each, CRs removed from the inputs): 10 public scripts, 4.7 MB (Ola Hallengren's MaintenanceSolution, sp_Blitz, sp_BlitzCache, sp_BlitzIndex, sp_BlitzFirst, sp_WhoIsActive, sp_QuickieStore, sp_HumanEvents, instnwnd, instpubs): 10 identical, 0 statements kept.
- **The PR's own comparison reproduces**: SQLDiff's 186 `.sql` files identical; `tsql.py` seeds 5001 to 5400 and `soup.py` seeds 5001 to 5400 identical (fresh seeds).
- **34 hand-written cases** (`reviews/pr-60-repro/cases/`: ELSE IF chains, CTE before INSERT, MERGE, cursors, triggers, functions, GO with a count, adjacent strings, unclosed string and comment, labels, window functions, operators, dotted names, non-ASCII words, EXEC forms, TRY/CATCH, sqlcmd lines, stray END/ELSE, BOM, empty text): 32 identical; the 2 that differ are findings 4 and 9 (lone CR).
- **Random pieces of the real scripts**: `windows.py` (1,500 pieces cut at any byte, half with tokens dropped, doubled or replaced) 36 differ; `lines.py` (2,500 runs of whole lines, the same mutations with BEGIN, END, ELSE, IF, parentheses, GO, TRY, CATCH, AS, SELECT, WITH, CASE) 24 differ. All 60 were shrunk with `reduce.py`; every one reduces to a case of finding 9. No difference in the statement tree or the layout.
- **Limits match sqldiff**: 990, 5,000 and 200,000 nested BEGINs, a 3,000-long ELSE IF chain and 200,000 nested parentheses give sqldiff's output under ASan and UBSan with no crash. Eight or more statements failing the check in one file keep the whole file, as sqldiff does.
- **A word that formatting would turn into a batch separator is caught**: `BEGIN go END` would put `go` alone on a line; the check sees it and keeps the statement (sqldiff: the same).
- **Ranges**: `range.c` formats [z, end), [a, z) and [0, a) one after the other and compares with the whole text formatted: 1,100 random ranges on two scripts, 0 differ.
- **Speed** (**measured**, `-O2`, 5 runs, `make check` running beside it): MaintenanceSolution.sql, 585 KB: 12.7 ms (12.4 to 17.1); a 100-byte range in it: 11.6 ms (11.4 to 15.3); the ten scripts 0.9 to 13 ms. sqldiff: 0.09 to 5.6 s on the same files. Formatting is one command, outside the redraw, so the 2 ms frame budget does not apply; one stall of under a frame at 60 Hz for a 585 KB file.
- **The PR's 19 plants**: see "Checks run".
- The non-T-SQL words in the layout (`limit`, `returning`, `natural`, `temporary`, `replace`) are in sqldiff's T-SQL path too (**measured**: same output on a text using them), so they are needed for the match.
- No `ref/sqlfmt.c` exists, so the ref-replacement rule has nothing to mirror.

## Second pass, at 410aaa8

Verdict: changes requested, for one item (A). Everything from the first pass that blocked is fixed.

The three blocking findings are fixed (**measured**, each rerun on 410aaa8):

1. `lookup`, `wname`, `is_space` and `closed` are gone. Words go through `tsql_word(w, n, &id)` once per token, and an unclosed token comes from `TsqlRd.open`. The layout's words are named once more as an X-macro, which the `W_*` enum needs.
2. `clauses()` walks the events with the previous and next token; the array and its limit are gone. `tokens65538.sql`, `bigvalues.sql` and the 200,000-token CASE now match sqldiff.
3. `tests/test_sqlfmt.txt` holds 479 texts with sqldiff's output and SQLDiff's commit on the first line. I ran `oracle/record.py` against my own sqldiff build at 1c4adab: the file reproduces byte for byte. Of my plants adapted to the new code (`extra-plants.txt`, 17 that apply), `test_sqlfmt` now catches 12 (was 5 of 16).

Also fixed: the NUL byte (finding 4); out of memory in the check (5: 657 allocation points, all return -1, the next call is right, no crash); comment runs (6: 5,000 lines 0.55 ms, 20,000 lines 2.5 ms, 5 runs each, was 4.8 and 75.6); memory (7: 1.0 MB held after the 585 KB file, which is the result itself, was 11.8 MB); the opening comment (8); the known differences (9, now in the file's comment, with `<<` and `>>` read as one operator after PR 58's change: `a>>2` keeps its gaps where sqldiff writes `a >> 2`).

Still the same as sqldiff: the 10 real scripts (4.7 MB), 34 of my cases (the lone CR aside), 183 of SQLDiff's 186 files (the 3 PostgreSQL files with `->>`, as the PR says), 600 fresh generator seeds (7001 to 7300), ranges (900 splits, 0 differ). 2,300 more random pieces of the real scripts (`lines.py` seed 5, `windows.py` seed 6): 40 differ, all reduced to the listed known differences. Speed is unchanged: 585 KB in 11.5 ms (11.0 to 15.1, 5 runs).
