## Findings

**A (blocking, fixed at 4945127).** A register name was taken as a map key. normal_mappable() accepted a trailing `"` in pend[], so `"-p` opened oil and then p put the unnamed register, and `" ` started a leader map. Neovim reads the register name with no_mapping (normal_cmd_get_more_chars): `"-p` puts register -, while `"a-` and `2-` still run the `-` map. Measured once against nvim 0.12.6 (`repro/nvim-regname.lua`, run with `nvim --clean --headless -n -u NONE -l`) and once on the PR with a probe test. Fixed with `if (pend[i] == '"') { if (++i == npend) return 0; }`, plus a test line and a plant.

**B (blocking, fixed at 4945127).** Keys replayed after a failed map skipped tools_key and git_key. On the dashboard, `SPC q` started recording a macro instead of quitting. Neovim checks the replayed q against buffer-local maps again (`repro/nvim-replay.lua`: hit=Q, not recording). In magit, `SPC s` would have run Vim s instead of staging. Fixed by `keys_input(e, key, pending)` in keys.h, which runs the whole chain. The replay calls keys_input, and main.c and test_keys_map call only it, so the chain copied between main.c and the test is gone. Re-probed at 4945127: dashboard `SPC q` quits; `"-p` puts "-; `2"a-` runs the map; `  x` matches Neovim.

**C (blocking, fixed at c0d8aa0).** `make win` (part of make check) failed to link. src/tools/check.sh links every wincc source except main.c, and keys.c now calls git_key and git_leader, but git is not in WIN_SRCS. `make wincc` passed because it only compiles. This was already broken at 6de18f6 through git_leader. Fixed with two stubs in tests/test_tools_win.c (thread 0's, agreed; PR 70 deletes them). Then `make win` passed all five modules (file, loop, shada, tools, win).

**D (blocking, fixed at 583eebb).** The tty plant "Render midcmd" patched main.c's old key-chain line, so planted.sh reported BROKEN PLANT. Fix: `repro/tty-plant.diff`, which changes the plant's text to `keys_input(&e, k`. It was measured caught by test_tty_render once.

Notes, not blocking:
- lead[3] fits today's longest map. The org maps in FEATURES.md 6 (SPC oxi, SPC oit) are 4 keys, so the size must grow with them. The author chose to leave that to the package that adds them, and the README says so.
- SPC i s (package 19) needs Visual mode, which `e->ks.visual` refuses today, so it will need a per-entry mode. The table is otherwise one string plus one switch case per map, which is easy to extend.
- A map typed while recording a macro is not recorded. This is listed in src/keys/README.
- The replay's last key passes pending=0 even when more typeahead waits (qn>0 is not carried through). Hypothesis: harmless, no case found.
