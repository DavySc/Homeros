## Findings and what became of them

**A. Heap use-after-free in `flush()` (blocking; fixed at `68eff27d`).**
At `c274a466`, `one` was a pointer into the pool kept across `fact()`,
which interns and so moves the pool. `uaf16.sql` (one SELECT of 16 bare
columns from one table, 164 bytes) under the Makefile's sanitizer flags:
`heap-use-after-free ... flush src/snip/snip.c:677`. The `-O2` build
answered rightly, by luck (3 runs). `test_snip` passed because none of
its files moved the pool inside a flush. Fix: `one` is an offset. New
test (8,000 bare names) and plant; the plant is caught. Measured at
`68eff27d`, `75659d49` and `58f421f4`: `uaf16.sql` and `corpus.sql`
clean under ASan.

**F. A plant of the PR was not caught (blocking; fixed at `75659d49`).**
"a bare name a column of any statement's first table"
(`ntab == 1 ? one : NULL` to `ntab ? one : NULL`) passed
`make test TESTS=snip` at `c274a466`, run with `tools/planted.sh` on a
copy holding that one plant, and with `test_snip` alone. `one` is the
statement's last table and the test looked only at the first. The test
now reads `from app, dom`; the plant is caught.

**B. T-SQL words offered as columns (not blocking; fixed at `75659d49`).**
At `68eff27d`, 10 of 31 words offered on `corpus.sql` were no columns
(`NOLOCK`, `PARTITION`, `COLLATE`, `int`, `max`, `day`, `NEXT`, `ROWS`,
`JSON`, `RECOMPILE`). Now a T-SQL word is a bare column only after a
comma, an operator or SELECT, WHERE, AND, OR, ON, BY, SET, HAVING, WHEN,
THEN, ELSE; other identifiers anywhere. Left, by measurement on
`probes/`: `matched` (WHEN MATCHED), `offset` (`desc offset 10 rows`),
and `, y = x` aliases after a comma in a SELECT (kept on purpose, see G).

**C. Data types ranked behind rare functions (not blocking; eased at
`75659d49`).** 95 common T-SQL words in an empty file (`rankcmp.py`), by
place after 2 letters: 39 better than main, 13 worse, 43 same; after 3:
19, 6, 57. The worse ones are data types (`date` 3 to 17, `int` 2 to
10). The words the file itself uses now rank with the reserved ones: with
`corpus.sql` in the buffer `da` offers `day date`, `in` offers `in int`,
`dec` offers `dec decimal`. In a file that has not used a type yet the
figures above stand (measured again at `58f421f4`).

**G. `, y = x` dropped real columns of UPDATE SET (new at `75659d49`;
fixed at `58f421f4`).** `set.sql`: `update dom set a = 1, b = 2, c = c + 1
where id = 3` gave `a c id`, not `b`. Now `y = x` is an alias only right
after SELECT; `set.sql` gives `a b c id`.

**D. Cand's comment gave the old ranks.** Fixed at `68eff27d`.

**E. First index build is slower (not blocking).** 700 KB file, first

## One mechanism, duplication

Bare names ride the existing `pairs` list (`of == -1`) and the existing
`flush`; the words a column follows extend the walk's one word table
(`COLUMN`, `SELECT` flags); the file's words are one byte array filled by
the same walk. No second parser or matcher. `make dupes` passes at
`c274a466` and `58f421f4` (1 run each); `tests/dupes-known.txt` and
`tests/owners.txt` are untouched.
