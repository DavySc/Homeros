## 2. Lost display or terminal

`backend.h`'s contract and `main.c`'s handling are right, but **this PR has no check that reaches the new `main.c` lines** (follow-up 1).

- `tests/hup.py` at the PR head, 5 runs: passes, with "exit status -1" each time. The editor is killed by SIGHUP's default action; `input()` never returns -1 (no backend does yet), so `lost` is never set. **measured**.
- Two review plants (`extra-plants.txt`): removing `if (n < 0) { lost = 1; ... }`, and removing the `if (lost) { ... return 1; }` exit so a lost display goes through `core_free`. Both **NOT CAUGHT** by `make test`. **measured**, 1 run.
- To see the path work, `tty-lost.diff` makes the terminal backend return -1 on POLLHUP (a stand-in for what package 6 will write) and `hup-ign.py` is `hup.py` with the editor ignoring SIGHUP. 3 runs each: **measured**

| main.c | Result |
|---|---|
| PR head | exit status 1 within 2 s, reopening recovers `hello` (no sanitizer or leak report) |
| without the `n < 0` line | still running 2 s after the hang-up (the spin of package 8's finding 4) |

So the mechanism is correct and both mistakes are visible once a backend returns -1. The journal needs no flush beyond the `journal_sync` of the current buffer: `journal.c` appends with `writev`, nothing is held in user memory, so the other buffers' records are already in the kernel.
