## Every plant runs exactly once (**measured**, `reviews/pr-176-repro/`)

`planted.sh` gives shard k/n the plant lines whose position p (from 0, over `cat tests/plants/*.txt` without comments and blank lines) has p mod n = k. So the shards 0/n to (n-1)/n split the list whatever its length (**proved**: each p has one remainder), and the only thing to check is that the workflow names each of 0/24 to 23/24 once and nothing else.

- `matrix.py` reads check.yml as YAML, takes the two strings out of the `fromJSON` expression and parses them as JSON: on the train branch 25 jobs, `check` plus 24 shards, k = 0..23 each once, every n = 24; elsewhere `["check"]`. `fail-fast: false` and `timeout-minutes: 180` unchanged. This matters more than usual: the long string is parsed only when the head branch is the train's, so a typo in it would pass this PR's own CI and break the next train.
- `part.sh` runs the selection for each shard the workflow names: 2,079 of main's 2,079 positions picked, 0 not exactly once; shard sizes 86 (9 shards) and 87 (15 shards).
- Four planted bugs, each seen to fail: shard 23 dropped (1,993 of 2,079 picked), shard 8 renamed 7 (87 positions twice, 87 never), one shard left at 5/16 (86 twice), a comma removed from the JSON (`JSONDecodeError`).
- `planted.sh`'s own guard takes 0/24 and 23/24 and refuses 24/24 (1 run each).
