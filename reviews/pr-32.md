## Findings

### 1. A driver crash under a known-difference rule counts as known (fix before the first entry)

`tools/conform.py` treats any case that is not the same as Neovim's and matches a rule as known. A driver that dies (ASan, UBSan, a signal) returns `{'error': ...}`, which is "not the same". **Measured**, 1 run (`reviews/pr-32-repro/known-crash.sh`): with a null write planted in `ref/keys.c` on Delete after a count and one entry for that rule, 1,500 sequences (seed 5) give "0 differ, 100 more are known differences" and exit 0. The same holds for an entry's example: a crash keeps it from ever going stale. Live conform is one of the sanitizer runs, and the first real entries (PR 20's core differences) will have broad rules. Fix: a result with `error` is never known, for cases and for examples. With the list empty nothing changes today, which is why this does not block.

I also reproduced the author's measurement: Delete after a count broken gives 73 of 1,500 differ without the list, and 0 differ with 73 known with the entry; a stale entry and an entry whose example does not match its own rule both fail the run (**measured**, 1 run each).

### 2. A wrong `SHARD` runs no plant and passes

**Measured** (`shard.sh`): `SHARD=4/4`, `SHARD=4` and `SHARD=x` each run nothing and exit 0. The workflow's four values are right, so this is only a guard against a later typo: refuse a shard that is not `k/n` with `k < n`, or print how many plants ran.

### 3. `planted.sh` can read org-conform's summary as a catch

Its pattern `[1-9][0-9]* differ` matches "0 of 2000 differ" (through "2000 differ", **measured** with grep). An `org-conform` plant that fails for another reason, such as Emacs missing, would be reported as caught. Either print the count first ("0 differ of 2000") or tighten the pattern when package 16 adds its plants.

### 4. Three `Buf` fields nobody reads or writes yet

`lastused`, `faces` and `nonumber` have no use on main, in `ref/core.c`, or at the current heads of the PRs named for them (23 and 29: `git grep`, no hit). By the top rule a field lands with its first user. Not blocking, since the packages need the header before they can push that use, but if either package drops its use the field goes too.

### 5. `lsp.h` says "ok" while DESIGN.md on main still says "simple"

PR 18's review blocked this same wording because it came without evidence. The evidence now exists: PR 27's review reproduced the gate (5 runs: "simple" hides Lean's diagnostics 3.2 to 9.0 s, "ok" 0 s), and DESIGN.md's phase 2 gate already says the edit log comes back in that case. The DESIGN.md rows (LSP, the models table, New approaches) are in PR 27, so between the two merges the header and the design disagree. Acceptable; PR 27 must not merge without those rows.
