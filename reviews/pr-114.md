## Changes requested

1. **Fuzz seeds over 256 bytes are cut** (Makefile `fuzz`). libFuzzer
   truncates every corpus input to `-max_len`, so a seed recipe meant for
   wire readers (a TDS login reply, a row packet) loses everything past byte
   256 and the fuzzer never reaches what the seed was for. Measured above.
   Smallest fix: pass `-max_len=256` only when there is no seed directory
   (libFuzzer then takes the largest seed), e.g. `m=-max_len=256` beside
   `c=`, cleared in the `if`. A plant for the recipe belongs with package
   22's first seeded fuzzer (no `tests/fuzz_<name>/` exists yet); say so in
   the comment or the PR body so it is not forgotten.

2. **The write wake can drop the read wake unseen** (tests/test_loop.c).
   Plant `w[i].ev = on ? POLLOUT : POLLIN` passes `make test TESTS=loop`.
   That bug hangs a client whose server answers before taking the whole
   request (SQL Server sends an error mid-batch, both sides' buffers full).
   Add to `write_wake`: with the wake on and the socket full, the peer
   writes a byte, `loop_once(1000)` wakes the watch. Also plant
   `for (int i = 0; i < 1; i++)` in `loop_write` survives because the test's
   watch sits in slot 0: watch a second fd first so the socket is not in the
   first slot.

3. **`str_addf`'s NUL restore is never run** (tests/test_str.c). Deleting
   `if (s->cap) s->s[s->n] = 0;` passes `make test TESTS=str`, though without
   it the string reads past `s.n` after a failure (measured above).
   glibc's vsnprintf returns -1 after writing for `%ls` of a lone surrogate
   (`L"\xD800"`), so a test needs no malloc failure: append `"abcdef%ls"`,
   expect -1, `s.n` unchanged and `s.s[s.n] == 0`. Add the plant.

4. **The test_str comment is broken**: line 2 to 3 of tests/test_str.c now
   read `the tail kept until its '` newline `' comes`; the `\n` became a real
   newline. Put `'\n'` back.

5. **No owners line for the dates** (tests/owners.txt). CLAUDE.md: "a new
   shared mechanism gets an owners line". `src/date/` is now the one place
   for civil dates; a telltale such as `719468|146097` owned by `src/date/*`
   stops the SQL client (or anyone) writing a second copy. (The loop's write
   wake has `POLLOUT` as a telltale too; `src/infoview/serve/serve.c`, a
   separate program, already uses it, so that line would need its exception.
   Optional.)
