# Review of PR 30: free replaced syntax trees in steps that ask stop

Reviewed head `729a04e` (it already holds main `8d08829`). Contract: `include/syntax.h`. Reviewer: a separate thread, briefed with the diff and the contract. Everything below was run; the drivers are in `reviews/pr-30-repro/` (`build.sh` builds them).

**Verdict: changes requested, all small.** The freeing itself is right as far as I could break it; finding 1 must be fixed before merge, findings 2 and 3 can go in the same push.**

## What the change is

`src/syntax/release.c` is tree-sitter's `ts_tree_delete` and `ts_subtree_release` with the walk's stack kept in a static between calls. `syntax_update` first frees pending nodes, 1,024 at a time, asking `stop` between steps; a tree replaced by a parse or dropped with its region is only queued. `syntax_free` frees all that is queued.

Read against tree-sitter's source at the pinned version (`tree.c:41`, `subtree.c:578`): the same statements in the same order, less the `__wasm__` branch (not compiled) and the subtree pool (made with capacity 0 in `ts_tree_delete`, so it frees directly). Nodes are reference counted, and a queued node keeps its count on each child until it is popped, so the new tree, the parser's reusable node and `ts_tree_edit` see a consistent tree at every step (**measured** below, not proved).

In `src/main.c` a finished parse returns 1, the frame is drawn, and the next `syntax_update` frees the old tree in the same idle period, stopping for a key. So the free does not wait for the next key, as the PR text says; it waits for the next frame.

## Findings

1. **`src/syntax/bench/run.sh` no longer builds** (fix before merge). It compiles `src/syntax/*.c` with its own flags, which lack tree-sitter's `lib/src`: `src/syntax/release.c:8:10: fatal error: atomic.h: No such file or directory` (**measured**, 1 run at the head). This is the script the PR cites for its second table. Adding `-I$syn/src/tree-sitter/lib/src` to its gcc line fixes it (how I ran it). `reviews/package-12-repro/build.sh` fails the same way; `reviews/pr-30-repro/build.sh` builds `gap.c` at this head.

2. **Three lines no check fails on** (`reviews/pr-30-repro/extra-plants.txt`, run once each with `extra-plants.sh`): 3 of 5 further plants are caught (a tree's included ranges kept, a node's child array kept, a child freed while still held). Not caught:
   - **x1, `ts_external_scanner_state_delete` removed**: `make test TESTS=syntax` passes. No test or fuzz input has a leaf whose scanner state is over 24 bytes. `reviews/pr-30-repro/scanstate.c` (40 nested block quotes in Markdown) is clean at the head and reports 7,500 leaked bytes with x1 (**measured**, 1 run each). Three lines of it in `test_syntax` plus the plant would close this.
   - **x4, `syntax_free` without `syntax_release(NULL, UINT32_MAX)`**: `make test TESTS=syntax` and 30 s of `fuzz_syntax` pass, because the queued nodes stay reachable from the static stack and LeakSanitizer does not report reachable memory. The line is right (without it a closed buffer's tree stays until some other buffer updates); say in the plants file that no check can see it, or find one that can.
   - **`if (!stack.size) array_delete(&stack);`**: deleting the line passes `make test TESTS=syntax` and my stress run under LeakSanitizer (1 run each). With it the stack is freed and grown again from 8 entries on every key; without it the stack grows to its largest and stays, as the redraw buffers do. One line less and fewer calls: delete it.

3. **The PR text overstates p99** (see the tables). The median and the count of keys over 0.86 ms are the supported claims; coding.c p99 in `gap.c` and everything on xdisp.c are inside the spread. Also say which coding.c (Emacs 31.1).

## Checked and fine

A later `src/<module>` header named `array.h`, `stack.h`, `tree.h`, `point.h`, `language.h`, `lexer.h`, `parser.h` or `unicode.h` is found in its own directory first. Residual risk is small.

## Open, not this PR's

- `syntax_free` still frees a whole tree without asking: 10.9 to 15.6 ms on xdisp.c, 2.7 to 4.1 ms on coding.c (**measured**, 5 runs). Same as before the PR. It matters when closing a buffer becomes a key Davy uses.
- `include/syntax.h` still says "at most 0.86 ms apart". After this PR that holds for the median key on every file measured and not for p99 or the first parse. Thread 0's header.
- release.c includes tree-sitter's internal headers, and `sources.nix` follows nixpkgs-unstable, so a tree-sitter update can change `TSTree` or `SubtreeHeapData` under it. A new owned field would leak and LeakSanitizer would say so in `test_syntax`; a change in how nodes are shared might not show (**hypothesis**). Read release.c against `tree.c` and `subtree.c` whenever the sources move.
