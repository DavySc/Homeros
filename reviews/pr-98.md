## 3. Notes for the next Org PR (none blocking)

**Note 1. A property drawer's `:END:`, and a test that is always true.** `sibling_ind` puts the new `:END:` at the drawer's column only for `ORG_DRAWER`. After a `:PROPERTIES:` line that was never closed and a stray `:LOGBOOK:` line, the new `:END:` closes a property drawer, and Org indents it as that drawer:

```
** NEXT                 Org:  ...                  the PR:  ...
    :PROPERTIES:                 :LOGBOOK:                    :LOGBOOK:
   :LOGBOOK:                     - State "WAIT" ...           - State "WAIT" ...
                                  :END:    (column 4)        :END:    (column 3)
```

10 of the 23 differing texts are this (`small/t00230.org`, `t01817.org` and eight more). The `lit(blanks(l), ":END:")` beside it is always true where it is reached: with it removed the driver prints the same bytes on 15,000 texts (**measured**). So one line does both, and is 9 characters shorter (`shorter-end.diff`):

```c
if (i < k) c = col(e[i].type == ORG_DRAWER || e[i].type == ORG_PROPERTY_DRAWER ? e[i].begin + h : prevl(l));
```

With it, 14 of the 9,000 texts differ instead of 23 (**measured**, 1 run): all 10 reduced texts then agree, and one of the 10 full texts still differs for one of the reasons below. The plant "an outer drawer's :END: indented as the line above" names the old text and needs the new one. The other 13 are Org's own oddities, the same on main: a whitespace-only first line in an existing LOGBOOK (4), a footnote definition between two `:LOGBOOK:` lines (6), a `:LOGBOOK:` line inside a source block or a LaTeX environment (3), where Org re-indents lines it has no business with. Not worth code.

**Note 2. An unclosed repeating stamp on a planning or property line.** On main too, and not about habits.

```
* TODO a
SCHEDULED: <2026-11-12 Thu +1d
```

Three steps right (`open/c.org`): Org ends at `* DONE a`, the PR at `* TODO a`. Org's `org-get-repeat` asks `org-at-timestamp-p 'agenda`, which wants a whole stamp around point before it looks at the line's kind; `agenda_ts` answers yes for any planning or property line. Also with text after the repeater (`open/e.org`) and in a property (`open/f.org`). The generator never leaves a stamp open on such a line. **Measured**, 3 texts, 1 run; main's `org.c` gives the same.

**Note 3. One rule no check holds.** `sibling_ind`'s "the sibling before has the same parent" survives `test_org` and the check's 500 texts when replaced by "the element before". A text that tells them apart, and on which the PR agrees with Org (`small/sibling-parent.org`, steps `rr`):

```
* TODO a
:NOTES:
  - item
    :logbook:
```

Org and the PR put the new drawer at column 2 (the list's), the mutant at column 0.

**Note 4. Words.** The PR body says the oracle "expects no further steps" after an Org error. `org_conform.py` cuts both answers at the error line (`a[:i]`, `b[:i]`), so what `org_todo_step` does on later steps is not looked at. That is right (each key is its own call; Org has no answer there), but it is not what the sentence says. And `sibling_ind`'s comment has one line of 130 columns.
