## Blocking findings

1. **A batch that ends with `EXEC` kills the connection.** `exec dbo.p`, `exec sp_who 1`, `exec sp_executesql N'select 1 a'` and a procedure that raises an error each show their rows and then fail with "the reply ends inside a token or before its last DONE", state DEAD (4 of 4). `exec dbo.p; select 2 b` works. The reply to such a batch ends with DONEPROC (0xFE) without DONE_MORE, and `token()` ends a run only on DONE (0xFD) (`tds.c:307`). Running a procedure is the commonest thing in a T-SQL session, so this cannot wait for PR 3.
   - Fix tried in a scratch copy: `k != 0xFF` instead of `k == 0xFD` on the BUSY/CANCEL line. All four batches then run, and cancel of a running EXEC still ends at DONE_ATTN (11 of 11).
   - It needs a test in `test_sql.c` (a batch ending in EXEC, one raising an error inside the procedure) and a plant. The oracle never sends EXEC, which is how 2,953 values passed over this.
   - SqlRun.tla has one kind of "done"; that is fine once the code treats both the same, but the comment at the DONE case should say which tokens end a reply.

2. **A Postgres cancel can cancel the next query.** A query is sent, its reply left unread 20 ms, `pg_cancel`, and on READY the next query follows at once: 35 of 60 next queries came back as "ERROR 57014: canceling statement due to user request" (16 of 20, then 19 of 40). Nobody cancelled them, and because `quiet` is off by then the error is shown.
   - Cause: `pg_io` closes the cancel connection as soon as its bytes are sent (`pg.c:191`), and ReadyForQuery ends the run whether or not the server has processed the cancel. libpq's `PQcancel` reads the cancel connection until the server closes it, which is the server's sign that the signal was sent.
   - Mechanism checked: the same probe with a cancel that waits for the server's close gives 0 of 40 (`probe pgrace2`). So: keep the run in PG_CANCEL until both ReadyForQuery has come and the cancel connection has been closed by the server.
   - No model: SqlRun.tla is TDS's cancel, which the server always acknowledges. Postgres's has no acknowledgement on the main connection, so OwnRows/EndsOnce do not carry over. CLAUDE.md asks for a model of a timing question with the property first and a broken variant; "closes the cancel connection at once" is that variant. The test needs the late-cancel case as TDS's has (`test_sql.c:157`).

3. **The database sockets are inherited by every child process.** `net_open` calls `socket(.., SOCK_STREAM, 0)` and `fcntl(F_SETFL, O_NONBLOCK)`; no close-on-exec. Login, fork and exec `sleep`, `tds_close`/`pg_close`: the server lists 2 sessions named homeros until the child dies, then 1 (both servers, 1 run each). In the editor every LSP server, terminal shell and `:make` started after connecting would keep the session, and an open transaction's locks, alive after the buffer closed it. Every other descriptor in the repo is close-on-exec; `src/infoview/serve/serve.c:379` has the one-call form (`SOCK_STREAM | SOCK_NONBLOCK | SOCK_CLOEXEC`), which also removes the `fcntl` line and `<fcntl.h>`. A test can do what `probe leak` does.

## Cheap, same push

4. **`memmove(NULL, .., 0)` at `tds.c:480`** when `tds_io(t, 1)` finds no byte yet (a spurious wake before the prelogin reply): UBSan stops the test build ("null pointer passed as argument 1"). `pg_io` in the same place is fine. Guard with `if (at)`.

5. **Checks with no test behind them** (my plants, `review-plants.txt`; `test_sql` exits 0 with each):
   - the host name is never checked (`SSL_set1_host` removed);
   - SCRAM: the server's proof is never checked; the server's nonce need not extend ours;
   - column names not escaped, on both servers (a tab in a column name then splits the header cell);
   - 57014 hidden outside a cancel too (a `statement_timeout` would vanish);
   - the password is kept after the login.
   The first three are the security checks of this PR. The SCRAM ones need no server: feed `pg_parse` the `R` messages of RFC 7677's example with `p->nonce` set (the struct is open), once right and once with a wrong `v=`. The host name: fetch the test server's certificate, pass it as `SSL_CERT_FILE`, and a checked login to 127.0.0.1 must fail with "mismatch" rather than "self-signed".

6. **varchar in a code page other than 1252 is shown wrong, silently.** `select cast(N'Ελληνικά' collate Greek_CI_AS as varchar(20))` shows `ÅëëçíéêÜ`. `put_char`'s comment says the server converts every collation to the client's code page; it does not (only UTF-8 collations arrive as nvarchar, which is why "a UTF-8 branch never ran"). Davy's servers are 1252 as far as memory says, so tables for other pages are not asked for (personal fit). Asked for: correct the comment, say it in README.md, and consider U+FFFD for bytes above 0x7F when the column's collation (the 5 bytes `typeinfo` skips) is not a 1252 one, so wrong text cannot be mistaken for data.

## Notes (not blocking; most are PR 3's)

7. **"Every type as SSMS shows it" is not exact** (README.md, PR text, plan):
   - float and real print C's `%g`: `1e+20`, `1e-07`, `1.2345678901234568e+17`. SSMS prints `1E+20`, `1E-07` (**hypothesis**: .NET's format; no SSMS here). The shortest-round-trip digits are a good choice; the exponent's letter and sign are the difference.
   - money prints 4 decimals (`1.2300`, `100.0000`), the oracle's CONVERT style 2. SSMS shows `1.23` and `100.00` (**hypothesis**: `SqlMoney.ToString` is "#0.00##"). Davy can settle both with `select cast(1.23 as money), cast(1e20 as float)` in SSMS; until then README should say "as the server's CONVERT shows it".
   - An error raised inside a procedure shows "Msg 50000, Level 16, State 1, Line 1" without "Procedure p,". PR 3 maps Line to a buffer line; for a message from a procedure that line is the procedure's, so the token's procedure name (now skipped) is needed to tell them apart.
   - "Changed database context to 'x'." (5701) and the language line (5703) land in `out` after login and after `use x`. sqlcmd shows them; SSMS does not (**hypothesis**).
8. **`net_open` blocks**, against `tds.h`'s "no blocking call": `getaddrinfo` is synchronous (how long with a dead resolver was not measured: this sandbox's lookups fail at once), and with the certificate check on, loading the CA store takes 16.4 to 23.8 ms per connect (3 runs; 0.2 to 1.9 ms trusted). One `SSL_CTX` kept for all connections would pay that once. Also only `getaddrinfo`'s first address is tried (**hypothesis**, from reading `net.c:54`; psql and sqlcmd try each).
9. **`copy t from stdin` waits for ever** (still busy after 30 s): the server asks for data and the client has none to send. psql would read stdin; here a CopyFail on `G` would end it with the server's error. `copy .. to stdout` drops its rows and shows only `(COPY 1)`.
10. **The server picks the SCRAM iteration count and PBKDF2 runs in one call**: 1,447 ms inside one `pg_io` for a role made with 5,000,000 iterations (4,096 is the default, about 1 ms). The cap is 2^31; a lower one would bound a hostile server.
11. **Binary values are 4 times slower than text per byte**: 20 MB of varbinary(max) takes 1,047 ms (1,021 to 1,097), 20 MB of varchar(max) 269 ms (220 to 306), 3 alternating runs. `put_hex` calls `str_addf("%02X")` once per byte.
12. **Copies**: UTF-16 surrogate pairs are now combined in four places and split in two (`lsp/json.c:174`, `infoview/scan.c:127`, `win/backend.c:123` and `:284`, `tds.c:38` and `:411`), each under the 50-token bar. PR 130 adds more UTF-16 for SSPI. Worth one pair of functions in `uni.h` (thread 0), with a `tests/owners.txt` line.
13. **A dropped network path** (laptop sleep, VPN) is not detected: no keep-alive and no `TCP_USER_TIMEOUT` (**hypothesis**; my probe with an iptables drop ended after 36 s with "the server closed the connection", which I could not attribute behind docker's proxy). SSMS's driver sets a 30 s keep-alive. The caller can always `tds_close`, so this is PR 3's to decide.
14. Small: `net.c`'s `fail()` passes `ERR_reason_error_string()` to `%s`, which is NULL when the error queue is empty (read, not triggered). `pg_cancel` goes through `net_open`, so each cancel builds an `SSL` it never uses. LOGIN7 names the workstation "homeros" where sqlcmd and SSMS send the machine's name (`sys.dm_exec_sessions.host_name`).
