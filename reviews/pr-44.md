## Findings

1. **The nightly does not test main.** A schedule fires on the repository's default branch, and this repository's default branch is `claude/project-thread-uxi928` (thread 0's branch), not `main`: `git ls-remote --symref origin HEAD` gives `ref: refs/heads/claude/project-thread-uxi928`, and GitHub's repository search says the same. **measured**. `actions/checkout` without `ref` then checks out that branch, so the nightly tests whatever thread 0 last pushed and stays green while a package merged to main since then differs from Neovim. That is a silent pass. Fix: `with: { ref: main }` on the checkout, and `git rev-parse HEAD` instead of `$GITHUB_SHA` in the issue text (it would name the default branch's commit). The workflow file itself is still read from the default branch, so better still Davy makes `main` the default branch; I have asked the coordinator to put that to Davy. PR 40's review assumed main was the default.
2. **The nightly's apt line lacks the Wayland packages.** With PR 33 merged, `make conform` needs `build/wl/protocols.o` (`make -n conform` on a trial merge of PR 33 runs `wayland-scanner` and links `-lwayland-client -lxkbcommon`). **measured**. The nightly would then fail every night on a missing library, and file that as "fresh-seed differences". Loud, not silent, but PR 33 is approved and waiting. Fix: the same apt line as `check.yml`.

Not blocking:

3. A job that hits `timeout-minutes` is cancelled, and `if: failure()` does not run for a cancelled job, so a hang against live nvim files no issue. **hypothesis** (GitHub's documented behaviour, not run). `timeout-minutes` on the make step instead makes it a failure. The step takes 2.5 min here.
4. `make` stops at the first failing target, so a conform difference hides that night's undo-diff result. `make -k` runs all three.
5. `org-conform` is empty until `src/org/` exists ("Nothing to be done"), so the nightly checks two things today, not three. Expected; it starts with package 16.
6. `-s` has no plant. Removing it is what tree A below is, and that is caught by hand only. A plant would need planted.sh to run itself; no planted.sh guard has one today.
7. Older than this PR: with TLC missing, a specs plant reads as caught (`want pass got error WRONG` matches `WRONG`). The filter should not count `got error`. **measured**, 1 run, same on main's planted.sh.
8. The carried `reviews/pr-38.md` and `reviews/pr-40.md` lack their final "Merge" sections (the project-file copies have them).
