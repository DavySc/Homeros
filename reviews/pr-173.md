## A. The speed claim holds (measured)

Per call, 2,000 calls per line, 5 runs each, pinned to one core while
`make check` ran on the other three. Median of the 5 runs' medians, with
the range of medians; p99 range over the 5 runs.

| catalog | call | median (range) | p99 range |
|---|---|---|---|

- The PR's 0.010-0.015 ms at 100k columns is reproduced (0.0104-0.0146).
  PR 172's review measured 3.9 ms per dot and 65 ms per buffer switch on
  the same amount of columns.
- The cost follows the number of tables, about 8 ns each, not the number
  of columns: twice the tables, twice the time (0.0105 to 0.0187 ms).
  At 100,000 tables one lookup is 0.85 ms with p99 up to 1.6 ms, under the
  2 ms gate for one call but not for three in one key. No database Davy
  named is near that; **hypothesis**: fine as it is. Residual risk noted
  for package 19: one call per table of the statement, per popup.

## B. Case and schemas (measured)

- SQL Server database `cs` (Latin1_General_CS_AS) with tables `Dom(Id,
  Kind, kind2)`, `dom(lower_only)`, `ZED(z)`: `dom`, `Dom` and `DOM` each
  give 4 rows, `dbo.dom.lower_only dbo.Dom.Id dbo.Dom.Kind dbo.Dom.kind2`;
  `zed` gives `dbo.ZED.z`. That is what the header says (ASCII case
  ignored), and fn gets each row's table name, so package 19 can keep the
  exact-case table when two come back (PR 172's finding E stays package
  19's to settle; in a case-insensitive database only one can exist).
- Postgres database with `a.x`, `b.x`, `b.y`, `public."X"`: `x` gives
  `a.x.c1 b.x.c2 public.X.upper` (every schema); the table list has 6.
- Non-ASCII case is not folded (`é` and `É` are two tables, each found
  only by its own name), as the header says.
- The empty name gives 0.

## C. :Connect (measured, 2 switches: ms to pg, pg to cs)

After `:Connect other` the lookup gives 0 at once and 1 s later (never the
old connection's columns), and the new connection's columns after the
next F5. PR 172's finding C cannot happen through this interface: the
call names the buffer, and the buffer's connection picks the catalog.
Unchanged from PR 168 and seen again: `:Connect name` empties that
connection's catalog for every buffer on it until the next login there.

## D. One mechanism, and the tests

- One walk (`row`) serves the index built at the read and the lookup;
  nothing else in the tree reads the catalog. With the table list and the
  per-table lookup package 19 needs no copy: tables after FROM (NULL), an
  alias's or a bare name's columns (one call per table), a schema's
  tables (the list, filtered on fn's schema).
- PR's plants in `tests/plants/sql.txt` for `test TESTS=sql_editor`: 60 of
  60 caught (`pr-plants.out`), the unplanted test passing 4 of 4.
- My 11 plants (`review-plants.txt`): 5 caught. Not caught, so tests owed
  in package 22's next PR:
  1. a lookup returns other tables' columns too (each table's rows run to
     the catalog's end): the test's callback keeps only `hcat` rows, and
     no count is compared; compare the returned count (5, 6 after `z`);
  2. a table matches a name it is a prefix of (`hca` for `hcat`) and
     3. the reverse: same cure, plus a lookup of `hca` expecting 1;
  4. the index compares the table name only (two schemas, one table each,
     same name: `a.x`, `b.x`) and
  5. only the first table of a name is returned: a second schema with a
     table of the same name;
  6. the empty name lists everything.
