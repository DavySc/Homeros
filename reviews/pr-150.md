## Findings

### 1. Blocking: another frame is drawn with this frame's Visual area, yank flash and :s match

`core_draw(e, t, g)` for a tab page that is not current calls `tab_use(e, t)`. That makes `e->win` and `e->buf` that tab's, while `e->ks.visual`, `vline`/`vcol`, `ks.yank` and `ks.inc` still belong to the frame the user types in. `visual()` in draw.c then measures the area from VIsual to the *other* tab's cursor and tests `w->buf != e->buf` against the other tab's buffer.

Repro, `test_zprobe_visual.c` (1 run, deterministic). Frame 1 shows a.txt and frame 2 shows b.txt, a different buffer. In frame 1, `Vj`, then frame 2 is drawn: **frame 2 has 15 Visual cells (0 before)**. After `yy` in frame 1, **frame 2 shows 4 yank-flash cells**. Neither should appear, because b.txt has no Visual area and no yank.

This is invisible today because main.c draws only tab 0. It shows on every Visual selection once thread 0's multi-window loop draws the other frames. Fix: the non-current draw should use the *current* window (and its buffer) for visual() and the cursor-line rule, not `e->win`. By Neovim's rule (win_line), a window in another frame on the *same* buffer may still show the area. My plant "another frame drawn with the command line and popup" (draw.c `if (!cur) return;` removed) is not caught either, so the non-current draw has no test at all. Please add one that covers the Visual area, the yank flash and the command line.

### 2. Blocking: a buffer refilled from one frame shows blank in another

`core_buf_fill` (core.c:248) clamps the cursors and tops of windows in `e->wins` only, the current tab page. It is used for git status, the compile buffer, the Lean goals and SQL results.

Repro, `test_zprobe_fill.c` (1 run). Frame 1 shows a 40-line file with the cursor on line 35. Frame 2 refills that buffer with 2 lines. Frame 1, drawn as its OS window shows it, then has **only `~` rows, 0 of the buffer's 2 lines**, until it is entered. Use `FOR_ALL_TAB_WINDOWS`, as the PR already does in adjust() and edit().

Follow-ups for other packages, not this PR: `tools/make.c` (put(), shown(), run()), `git/keys.c` git_aux_shown, `lsp/lsp.c` lsp_goals_toggle, `shada.c` and `kitten.c` loop over `e->wins` too. With frames on three monitors, "shown" should mean shown in any frame, and the compile output should follow in a frame that is not current. `FOR_ALL_TAB_WINDOWS` lives in core_int.h, so those packages cannot use it. One public way, through core.h (thread 0), would keep it to one mechanism.

### 3. Blocking: the Wayland and image speed benches no longer build

`make build/wl/bench` (package 8's performance gate, src/wl/build.mk:21) fails with `too few arguments to function 'backend_wl.input'` and the same for `size`, `ready` and `present` (1 run). The PR updated only its core_draw line. `src/image/bench/frame.c` calls `backend_wl.input/size/cell/ready/present` with the old signatures too. No check builds either file, so CI stays green. Please update both. Building the benches in `make compilers` would be thread 0's follow-up, so the next header change cannot break them unseen.

### 4. Blocking: Focus.tla is cited but not in design/specs

keys.h, wl.c, backend.c and both tests cite Focus.tla for KEY_RAISED's order, but the model is only in /mnt/project-files/frames/focus, so `make specs` never checks it. CLAUDE.md: "Timing questions ... get a TLA+ model checked by TLC, with the property stated before the mechanism and at least one broken variant". PR 132's review (finding 5) asked for it before the backends. The model is ready: it passes and fails as each cfg expects (table above). It needs to be moved into design/specs with its 7 cfgs, given a DESIGN.md row next to Frames, and given a plant line, for example "Focus_ok Variant asked -> enter", caught by `make specs`.

### 5. Asked: the screen test lost 57% of its buffer-command cases

In tests/test_core_screens.py the new tab slice `elif c < .31` was carved out of the buffer slice (.25 to .35), so `e:`, `b:`, `bn`, `bp`, `alt`, `enew` and `bd` went from 10% to 4% of tokens. Counted in the recorded file: **267 such tokens on main, 115 on the PR** (of about 2,800). Please give the tab tokens their own share without shrinking another, for example by scaling the thresholds. Coverage elsewhere should not pay for frames.

## Notes (not blocking)

- **Merge order with PR 140.** The two conflict in 10 files: font.h, font.c, win/backend.c, wl.c, test_win.c, test_wl.c and the font/image/win/wl plants. PR 140 (with 135) is approved and rejoins the next train once it builds on main. Whichever lands second redoes its Windows backend port. I told the author thread on 2026-11-24; the merge queue should pick the order.
- **Merging before main.c.** main.c still draws tab 0's window only. If this PR lands before thread 0's multi-window loop, SPC 5 2 in the GUI switches the one window to the new tab page with no tabline and no second window, and SPC 5 keys are live in which-key. Better to land both in one train, or keep a trial build off that main.
- **`:tabnew`, `:tab split`, `:tabclose` and `:tabonly`** exist as core functions and screen-test tokens, but not as Ex commands. The PR text reads as if they do. Davy uses the SPC 5 keys, so that is fine; just say so in the text.
- **SPC 5 f** makes the frame before the picker opens, so cancelling the picker leaves an extra frame. Emacs's find-file-other-frame prompts first.
- **KEY_CLOSE** in keys.c still runs `core_close(e, 0)` on the current window. keys.h now says ":tabclose for its tab page, :qa for the last", which needs main.c to route it by window. Before this PR, the X button with splits closed one split, not the editor. That predates this PR, and thread 0's main.c should get it right.
- `win_of()` in wl.c and win/backend.c is the same walk with `next`/`link`. The two never build together, so this is not duplication in one binary. Noting it only because the dupes rule covers renamed copies.
- tools/planted.sh's new filter (`^error: `, `No space left`) can only turn a catch into "FAILED OTHERWISE", never the reverse, so it does not weaken the plants.
- Real Windows: SetForegroundWindow to our own other window delivered WM_SETFOCUS inside the call in all 120 raises, matching the PR's claim (measured under Wine) and Focus.tla's Windows interleaving.
