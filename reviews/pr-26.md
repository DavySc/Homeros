## Findings

### 1. Sixty-four keys of one unfinished command leave Normal mode dead (blocking)

`normal_key()` keeps the half-typed command in `pend[64]` and drops any key once it is full; `run()` then asks for more keys for ever. Nothing gets out: Esc is dropped too.

Repro: `reviews/pr-26-repro/stuck.sh D`. 63 digits then `x` works; 64 digits then `x` never returns (the driver's closing Esc loop spins; exit 124 after 10 s). A digit key held down for two seconds does it. Neovim caps the count at 99,999,999 and carries on. `fuzz_keys_all` cannot see it: it never checks `ks.pending` after its closing Esc, and it only has the digits 1, 2 and 3.

Fix: do not store the count's digits (Neovim keeps a number), or at least make Esc always clear `pend`. Add the case to the recorded traces with a plant.

### 2. Commands work on code points, Neovim on whole characters (blocking)

`clen()`, `head()`, `inc()`, `dec()` step by `uni_len`/`uni_prev`. Neovim 0.12 steps by grapheme cluster (`utfc_ptr2len`), and `uni_glen`/`uni_gprev` are on main, proved, and unused by `src/keys`. Hand cases, 16 of 17 differ (`one.py`):

| Text | Keys | Neovim | PR |
|---|---|---|---|
| `e◌́a b` (e + U+0301) | `x` | `a b` | `◌́a b` (a stray mark) |
| same | `l x` | `é b`, cursor 3 | `ea b`, cursor 1 (inside the character) |
| same | `r x`, `v d`, `y l P`, `a x Esc`, `i Del` | whole character | half of it |
| `aé` | `$` | byte 1 | byte 2 (on the mark) |
| `🇳🇱b` | `x` | `b` | `🇱b` |
| `👨‍👩‍👧b` | `x` | `b` | `ZWJ 👩 ZWJ 👧 b` |
| `a👍🏽b` | `l x` | `ab` | `a🏽b` |

Random text with such characters: 34 of 300 sequences differ (`gen2.py D 300 5 wide`), against about 1.5% on conform.py's text. conform.py's WORDS have no such character, so the 1,031 traces cannot see it; add some.

### 3. Random runs differ outside the listed gaps (blocking: the list must be true)

The PR says every difference traced was a listed gap. Of the 15 differences at seed 101 (`base-101.json`, first differing prefix by `first.py`), 8 are on the list (Visual `Q`; `gv` after edits twice; C-o, C-u or C-d reaching Normal mode after a change whose motion failed, four times; multi-line change then `u`), 5 are not (a, b, c, e, f below) and 2 I did not settle. Cut down, each reproduced every time:

| # | Text | Keys | Neovim | PR |
|---|---|---|---|---|
| a | `ab cd ef⏎gh ij kl` | `j w C-v D k` | cursor (1, 2) | (1, 3) |
| b | `ab⏎⏎cd` | `x j d i w u` | `ab`, cursor (1, 0): the `x` is undone | `b`, cursor (2, 0): `diw` on an empty line made an undo step |
| c | `Foo.⏎ab` | `j A C-o x Up y Esc` | `Fyoo.` | `yFoo.` |
| d | `Foo.⏎abc` | `j $ i C-o x Up Esc` | cursor (1, 1) | (1, 0) |
| e | tab `é é 0x1f 7 0x1f⏎∀ bar_1` | `W C Down CR Esc C C-o u Esc A C-o u` | cursor (2, 8) | (2, 7) |
| f | tab `-3 𐐀x` | `C-v $ ~` | `-3 x` + 6 spaces + `𐐨` (Neovim garbles it) | `-3 𐐨X` |
| g | number with 150 leading zeros | `C-a` | 151 digits | cut to 101 digits (`buf1[200]`, zeros capped at 100) |

(a) and (b) are plain ASCII and everyday keys. (f) is Neovim's bug, but it belongs on the list like the split character on Visual `A`. Two more seed-101 cases (`2Q` after an appended recording, and insert `C-o dd` then typing) differ and I did not cut them down; they are cases 10 and 12 of `base-101.json`.

The listed `4cc Esc u` gap is wider than it reads: `V j c Esc u`, `2cc Esc u`, `j 2S x Esc u` all leave the cursor a line off. That is daily use, so it needs an owner before acceptance.

`%`: with matchit never loaded (`NOMATCHIT=1 gen2.py D 400 7 pct`) 396 of 400 match and the 4 that differ first differ at a scroll or jump key (`first.py`), so the built-in `%` is right. Suggest the harness loads Neovim with `--cmd 'let g:loaded_matchit=1'` and types `%`, instead of leaving it out. Davy's Neovim does have matchit, which differs on some lines (`%` on `a /* x */ (b)` goes to byte 7, built-in to 12): say in FEATURES.md which one is meant.

### 4. Keys in FEATURES.md section 2 that are not built and not listed (blocking: list them in the repo)

`keys.h` says package 5 grows the keys to FEATURES.md. Not built (each run against Neovim, `single.py`, 65 of 164 differ): search `/ ? n N * #` and as a motion (`d/x`); operators `= gq !` and `gc`; tag objects `it at`; registers `"+ "* "/`; every ex command but `:w :q :wq :x` (`:s`, `:g`, `:norm`, ranges, `:5`, `:d`, `:y`); insert `C-k` digraphs; `gi`; plus what the PR does list (marks, jump and change lists, scroll keys). An unbuilt key is not ignored: its letters run as other commands. `/foo⏎` runs `f o`, `o`, Enter and leaves 10 lines where there were 8.

`tools/conform.py` points to `src/keys/README` for the gaps; there is no such file. Put the list there (or in FEATURES.md), with what waits for whom, and either title the PR as the first part of package 5 or build the rest. The acceptance line (10,000 random sequences match) is not met yet: about 1.8% differ.

### 5. `fuzz_keys_all` fails or passes by chance, and one conform plant proves nothing (blocking)

- The fuzzer feeds digits, so one key can ask for 333,333 opened lines or 222,222,222 puts. 7 of 7 runs of 30 s failed here (3 of them on an idle machine): `333333o…` and `3333333333O` time out (20 s limit), `222222222p` runs out of memory. CI passed once. The last one is not the rope's slowness. Bound the count the fuzzer can type.
- Its plant (`tilde steps one byte`) was not caught in 2 of 4 runs (60 s passed with the bug in), and the other 2 runs failed on a count timeout, which is not the plant.
- Registers, redo and the last insert carry over between inputs, so an artifact does not replay: the check's artifact (`| h . p p R s C-r R`) runs alone in 0.07 s. Reset the state per input.
- `keys: Lean symbols are word characters again (live nvim)` runs `make conform SEED=1`, which fails without the plant too (36 of 2,000 differ; 51 with it). A check that is red anyway catches nothing. Move the plant to the recorded traces, which are green.

### 6. `ref/keys.c` is dead and still edited (blocking, small)

With `src/keys/*.c` present the Makefile no longer builds `ref/keys.c` (439 lines), yet the PR adds 48 lines to it. Rule agreed with thread 0: the PR mirrors what the ref file gained on main and deletes it. Mirrored already: KEY_CLOSE, Del, the join. Delete the file and fix the three comments that name it (`keys.h`, `keys.c` twice, `ops.c`).

### 7. Notes, not blocking

- conform.py compares lines and cursor only; DESIGN.md says registers must match too. For thread 0, now that registers exist.
- A mouse or wheel key in Normal mode is an unknown command and cancels a half-typed one: `2`, wheel, `x` deletes 1 character, not 2 (measured, 1 run). For when a window backend sends them.
- `test_file_core.c` on cf8a8cb is package 11's change from PR 25; its review belongs there.

### What blocks the merge

1. Neovim's side needs `scrolloff=6` (FEATURES.md's setting; the core has it). Without it every scroll key differs on `DC` (`C-d` on 60 lines: line 12 against 18). With it 16 of 16 hand cases match (`C-d C-u C-e C-y H M L zt zz zb`, with counts).

3. The generator still reaches keys the README lists as unbuilt (CTRL-O in Normal mode after a change whose motion fails, Visual `@` and `Q`). DESIGN.md says "random sequences from the supported subset": keep them out until they are built.
4. Differences that are not on the README's list, each reproduced every time (`one.py`, on `DC`; N1, N2, N3 and N5 also on `DR`):
