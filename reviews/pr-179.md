## Findings

Each was reproduced by running it; counts are runs with the same result.

### 1. A database whose name holds a space cannot be picked (blocking)

`sql_connect` cuts its argument at the first space to drop the picker's
mark (`strcspn(name, " ")`). **Measured**, 3 of 3 (`p179 spacedb`): the
picker lists `srv/my db`; Enter gives connection `srv/my`, and F5 answers
"Login failed for user 'sa'" (Msg 18456), which points at the password, not
at the name. `:Connect srv/my db` typed by hand does the same. Postgres, 3
of 3 (`p179 pgspace`): `pgs/My Db` becomes `pgs/My`, "database "My" does
not exist". SSMS lists and opens such databases, and Davy's work servers
are not ours to rename.

Wanted: only the mark is cut (the exact ` ✓` at the end), or the picker
hands over the item without it; a test with a database whose name holds a
space, picked and typed.

### 2. sql_pick reads past its stack buffer (blocking)

`sql_pick` builds `name/db` in `char d[600]` and gives `str_add` the length
`snprintf` returns, which is the untruncated one. A connection name of 250
bytes (the file allows 255) with a database name of 128 CJK characters (384
bytes, SQL Server's limit): **measured**, 3 of 3 (`p179 long`), ASan:
"stack-buffer-overflow ... READ of size 636" in `str_add` from
`sql_pick` (sql.c:861), reached from `catwake` when the databases arrive.
Far from Davy's file, but the project's bar is that no input crashes or
reads out of bounds, and the fix is a size (256 + 1 + 4 × 128 fits no 600)
or a clamp.

### 3. Commented-out and unusable lines are listed (should fix)

The picker has its own reader of the connections file (`sscanf` of two
words), beside `lookup`'s. It does not skip `#` and does not ask for five
fields. **Measured**, 3 of 3 (`p179 list`): `#old mssql 10.0.0.1 sa master
pass=x` is listed as `#old`, and `half mssql` as `half`; Enter on either
says "no connection #old". Commenting a connection out is the usual way to
park one. One reader for the file (the owner of "a connections-file line")
would also answer the one-mechanism rule: two parsers of one format will
drift.

### 4. The terminal's keys do not count as "a key comes first" (should fix)

`pickfor` is cleared in `sql_key`, but `keys_input` asks `tools_key`
first, and `term_key` takes Ctrl+. and every key while the terminal is open.
**Measured**, 3 of 3 (`p179 term`): pick `srv`, press Ctrl+. and type in the
shell before the databases come; the picker opens under the terminal (its
title shows above the terminal's box), the keys keep going to the shell,
and when the terminal shuts the picker is there waiting. With a server that
takes seconds to answer (VPN), opening the terminal meanwhile is likely.
Wanted: the picker opens again only if nothing else took a key, for example
by not opening when the terminal is open, plus a test.

This mechanism (a background read that opens a modal window unless a key
came) is a timing rule and has no model: `design/specs/SqlCat.tla` still
starts a read only from a login or fn NULL, and the PR adds a third start
(`:Connect` on a server alone, with no session logged in) and the
`pickfor` flag. CLAUDE.md asks for the property first and a broken variant
that fails. A `Pick` step and the property "the picker opens only if no key
came since the pick" belong there.

### 5. No connections file: an empty picker and no word why (should fix)

**Measured**, 2 of 2 (`p179 nofile`): with no `homeros/sql` file,
`:Connect` opens an empty picker (0/0) and the message line is empty.
Before this PR `:Connect` said "sql: not connected", and F5 still says "no
connections file ... (src/sql/README.md)". On a new machine this is the
first thing Davy sees.

### 6. `*live` is returned and never used (simplify, thread 0's header)

Both callers ignore it: `draw_status` and pick.c's `snippets` pass an
`int live` and never read it, because the mark is already in the string
(`marked`). Only the test reads it. Two ways to say "live" for one fact;
dropping the parameter from `sql_pick` and `sql_status` is less code and
one mechanism. (My plant "the status line's live flag never set" is caught
only by the test's own `&& live`.)

### 7. Smaller things (not blocking)

- `tests/test_keys_map.c` includes `tools.h` twice.
- The status line shows no connection until the first key (`p179 first`,
  2 of 2): `conn` needs `E`, which only `sql_key` and the commands set.
  A file opened from the command line shows `first.sql` without `ms` until
  a key is pressed.
- The connections picker draws the empty preview pane under the list
  (every screen in `p179.out`); a list-only layout would fit.
- `conn` looks the folder's connection up once per buffer (`looked`): a
  `dir` line added later shows in the status line only after F5 or
  `:Connect`. Fine, but the README could say so.
- `:Connect ms/` (an empty database) is taken as the server's default
  (`p179 dir`); harmless.
- pick.c and draw.c are packages 15's and 4's; the commit says thread 0
  agreed to package 22's stand-in lines. Noted, not checked with thread 0.

### 8. The PR's plants

26 of 26 compile with both compilers and are caught. "the picker lists no
connections" is caught by UBSan at pick.c:220 (a null pointer passed where
none is allowed) and not by a CHECK of the test; a CHECK on the listed
items would say what broke.

### 9. My plants: 9 of 14 not caught (the gate is thin on names)

Not caught (`plants.out`), each a rule the PR states:

| Plant | What would ship |
|---|---|
| a name matches a longer name's start (`!a[0][wn]` dropped) | `:Connect sr` connects `srv` |
| name/db on a server-alone line counts as alone | picking `srv/hcs` logs in again for the list and pops the picker up |
| every database of a live server marked live | `srv ✓` and all `srv/...` marked |
| srvx lists srv's databases (the `/` check dropped) | a connection whose name starts with another's shows its databases |
| the folder's connection looked up at every frame | the file read per redraw (sql.h: "reads the connections file once") |
| a connection previewed as a file | the preview pane tries to open `srv/master` |
| Postgres's templates listed | `pgs/template0`, `pgs/template1` in the picker |
| a failed read keeps the picker waiting | harmless today (a key clears it) |
| the status line's connection on every buffer | an empty connection drawn |

Wanted with the fixes: tests for the first five and the templates (a
`!strstr(picked(), "template")`, a prefix name in the test's file, a live
`srv` with unmarked `srv/...` items, a count of file reads or of lookups).
