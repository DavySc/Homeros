same: (A) nested hanging parentheses collapse onto the outer one, a
regression from main on ordinary subqueries; (B) a stale parenthesis stack
gives negative indents in the next statement, which Homeros prints at
column 0 and on which sqldiff 2da1577 panics.

## Blocking

**A. A hanging `(` inside a hanging `(` collapses onto the outer one.**
`column()` subtracts one step per hanging parenthesis open at the level
(`hangs`) and one more for the parenthesis itself (`open`), so every
nested hanging `(` lands on the outer one's column and its contents on the
outer's contents. Repro `nested.sql` (EXISTS holding an IN subquery) and
`cte.sql` (a CTE holding one), both ordinary in Davy's T-SQL:

```
where exists
(
    select 1
    from u
    where u.a in
(                      <- main: 8 spaces; the rule asks 4
    select b           <- same column as `select 1`; the rule asks 8
    from v
)
    and u.c = 1
)
```

main indented this by depth (inner `(` at 8, `select b` at 12). The rule
in the PR's own words, "what it holds sits one step in from it", puts the
inner `(` with its siblings (4) and `select b` at 8. One model that gives
that and keeps every recorded case: only a hanging `(` at depth 0 pulls
back a step; a nested hanging `(` sits with its siblings and its contents
go one step in, as any parenthesis. Fix in layout.rs too, record both
repro texts, and add a plant.

**B. The parenthesis stack outlives its statement.** `par` is cleared
once per render, not per statement, and a `)` pops it, so an unclosed
hanging `(` leaves entries that `hangs()` counts in the next statement,
whose `depth` restarts from its own base. `column()` then returns a
negative indent: Homeros writes the line at column 0 (probe: an abort in
`newline()` when the indent is below 0 fires with -4), and sqldiff
2da1577 panics (`capacity overflow` in `layout::render`, exit 101; usize
underflow in `t.level + 1 + t.depth - hangs - open`); sqldiff main formats
the same text. Minimal `stale-min.sql` = `T\n(\n(\n;A\n!`. Realistic
`stale.sql`, a half-typed parenthesis followed by format on save:

```
select 1 where x in
(
(
1
;
select a
from t
where b = 1
and
c = 2           <- printed at column 0; main and the rule: 4
```

Found by soup.py seed 3383. Whatever the fix (clear the stack when a
statement starts, or count only parentheses that enclose the token), the
indent must not be able to go below the level; record `stale.sql` and add
a plant.

## Non-blocking

**C. Shorter, same output.** `column()`'s `open` argument is always
`allman(p, c)` (both callers pass it for the same token), so the
parameter goes from `column()` and `indent_of()`, and `indent_of()` loses
its first line (`c != i &&` guards the footer case). `lined_` goes too:
`newline()` sets `head_` itself after writing the indent, which is the
same moment for every reader of `head_`. `simplify.diff`: 4 lines and one
global fewer; identical output on 2,883 inputs (the 483 recorded, 800 each
of tsql.py, soup.py, parens.py; 1 run). The same two apply to layout.rs
(`allman(text, toks, c)` passed as `open`, the `lined` flag).

**D. Questions for Davy (layout, not code).** In a CTE list the second
name now sits at 4 while its `(` hangs at 0 (`),` / `    b as` / `(`); on
main both sat at 4. And AND/OR inside a subquery or a CTE body get no
river (record.py case 3 records this, since clauses inside parentheses are
not broken); worth asking whether he wants the river there too.
