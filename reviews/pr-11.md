## Findings

### 1. `core_scroll` is said to fail with a beep where Neovim does not beep (blocks)

`core.h` now says of `core_scroll`, `core_scroll_half` and `core_scroll_page`: "The first three return 0, or -1 when they could not move (Neovim beeps, which ends a macro or mapping)."

`scroll.vim` asks Neovim 0.12.6 (**measured**, 5 runs, the same each time). A beep ends `:normal`, so an `x` after the key runs only if the key did not beep:

| Key | Where | Neovim |
|---|---|---|
| CTRL-E | last line already on top | does not move, **no beep** |
| CTRL-Y | line 1 already on top | does not move, **no beep** |
| CTRL-D | on the last line | beep |
| CTRL-U | on line 1 | beep |
| CTRL-F | last line on top | beep |
| CTRL-B | on line 1 | beep |

So the comment is right for the half and the page and wrong for `core_scroll`. Package 5 asked for the result in order to beep; coded as the header says, `qa` CTRL-E `x` `q` replayed at the end of a buffer stops before the `x`, and Neovim's does not. Smallest fix: `core_scroll` stays `void`, and the comment names only the two that beep.

### 2. After this PR and PR 13 the terminal still does not use the table (does not block; needs a follow-up)

The Makefile builds `src/tty/tty.c`, not `ref/tty.c`, since PR 2. PR 13 gives `src/tty/tty.c` its own copy of the 91 escape strings. So with both merged, `faces[]` is linked into the editor and read by nothing: `grep -rn 'faces\[' src/` is empty (**measured**), and with the label colour in `ref/theme.c` changed to `1, 2, 3` in that merged tree, `make test TESTS="grid grid_diff tty_render"` still passes (**measured**, 1 run). The table exists three times (`ref/theme.c`, `src/tty/tty.c`, and `src/win/backend.c` on PR 3) until packages 6 and 9 switch to it.

That is package 6's and package 9's work, not this PR's, but the PR text says "the terminal and window backends share one table" and nothing in the tree holds anyone to it. Asked for: the follow-up named in the PR text, and a plant for the table (a wrong colour in `ref/theme.c` caught by a terminal test) once `src/tty` reads it.

### 3. A window backend still needs three theme colours the table does not hold (does not block)

`grid.h` says a face without `FACE_FG` or `FACE_BG` takes "the terminal's or window's default". A terminal has defaults; a window has none, so each window backend must bring its own. `window.c` prints what the table gives (**measured**, 1 run): for plain text, a line number (`ATTR_DIM`) and the status line (`ATTR_REV`) it gives no colour at all. PR 3's `src/win/backend.c` line 47 shows the consequence: `TEXT`, `DIMC` (overlay0) and `BASE` are its own constants, and the two Wayland builds will each choose theirs. The flavour toggle FEATURES.md lists would then change the table and three backends.

Suggested, in this PR while the header is open: the theme's text, dim and base colours next to `faces[]` (three more RGB triples), which the terminal ignores.

### 4. `Win.jump[]` holds a `Buf *` and nothing says what `:bd` does to it (does not block)

`bd.vim` (**measured**, 1 run): Neovim 0.12's default `jumpoptions=clean` drops a deleted buffer's entries from the jump list (`[[1,1],[1,5],[1,10],[2,1]]` becomes `[[2,1]]`). With a pointer in each entry, a core that frees the buffer and leaves the entries has a dangling pointer on the next CTRL-O. One sentence on `core_buf_delete` or on `jump[]` settles it for package 4: `:bd` removes that buffer's entries from every window's list.
