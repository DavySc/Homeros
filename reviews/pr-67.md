# Review of PR 67: gq (sqlfmt for .sql, Neovim's format_lines elsewhere), :Format, format on save

Reviewer: a separate Fable 5.2 thread ("Review gq formatting PR 67"), 2026-11-18. Briefed with the diff and the rules, not with the author's conclusions. Every finding below was reproduced by running it; the files are in `reviews/pr-67-repro/`.

## First pass: head f2dfeae (already on main d4646c4). Changes requested

One blocking finding (A). B, C, F and G are differences from Neovim that must be fixed or listed; D and E are duplication and a wrong search path.

### Findings

**A. Blocking: after a SQL format the cursor is left where it was, also outside the buffer; the next key can crash.** (measured, each sequence 1 run under ASan)

`b.sql` is `select 1`, seven empty lines, `SELECT   2,   3 FROM t`. sqlfmt folds the empty lines, so 9 lines become 4.

| Keys | Result |
|---|---|
| `G:Format<CR>` | cursor on line 9 of 4 |
| `G:Format<CR>x`, `...D`, `...vd` | ASan: requested allocation size 0xfffffffffffffff9, `edit` core.c:981 from `op_delete` ops.c:399 |
| `G:w<CR>x` with a `sqldiff.toml` | the same crash |
| `7GgqGx`, `8GgqjD` | the same crash |
| `Go garbage (((<Esc>:Format<CR>` | cursor [7,14] on a line of 9 bytes; its text is now line 11 |

`sql_format()` calls `core_edit()` and never touches `W->line` or `W->col`; `op_format()`'s `check_cursor_col()` clamps only the column. So every format that changes the line count above the cursor leaves it on other text, and one that shortens the buffer leaves it outside. Format on save does this on a plain `:w`. Davy's conform.nvim keeps the cursor on its text (hypothesis: from conform's documentation, not run here).

Wanted: the cursor valid and on the text it was on; tests that type keys after the format; plants; and a fuzzer on a `.sql` path, since `fuzz_keys` never reaches the SQL hooks.

**B. Fix or list: other windows' cursors after gq.** (measured, 1 run; found by `gq.py mix`, seed 11)

Text `aaa bbb ... zzz` (102 bytes) and `second line`. Keys `$<C-w>sgqq<C-w>w`: Neovim [2,22], ours [1,78]. Neovim's `internal_format()` breaks with `open_line(OPENLINE_MARKFIX)`, which calls `mark_col_adjust()`, so marks and other windows' cursors after the break go to the new line. Replacing the blanks with a line break does not. The same will hold for a-z marks once keys reads them.

This is a residual risk of the PR's own mechanism (a forward scan and one replace per break, where Neovim moves the rest of the line each time). CLAUDE.md asks for a row in DESIGN.md's "New approaches" table for it: the alternative compared, the scenarios, the evidence, the residual risk. The text and timing evidence is good (below); the row is missing.

**C. Fix or list: `u` after a gq that changed nothing.** (measured)

`a b c d\n\ne\n`, keys `Ggqggu`: Neovim [3,0], ours [1,0]. Seven of my reduced cases are this one.

**D. Duplication and length** (Davy, 2026-11-18)

- ops.c:1701, `for (long i = 0; s[i] == ' ' || s[i] == '\t'; i++) ind += ...` is `get_indent(l)` (buf.c:283), which `format_lines()` calls ten lines further down.
- `is_sql()` repeats the test in `syntax_open()` (syntax.c:332). One shared function through `include/` (thread 0).
- `ex_write()` builds an absolute path by hand (getcwd, join, drive letters): 12 lines. `state_abs()` in src/file/state.c does it for Linux and Windows. Exported through `include/file.h` (thread 0), it shortens `ex_write()` and fixes E.

**E. The search for sqldiff.toml takes a wrong directory for a path with `..`.** (measured)

Working directory `t/a/b` holding `sqldiff.toml`, file `../x/q.sql`: `:w` formats, though `a/b` is not above the file. The walk strips components of `t/a/b/../x/` as text.

**F. Fix or list: the wanted column after gq.** (measured)

` of\x0cdo,` with `vgqgo`: Neovim [1,0], ours [1,1]. 80 spaces and `a` with `gqgggqlgg`: Neovim [1,79], ours [1,80]. Neovim keeps its old curswant over gq.

**G. Fix or list: Tab typed after two gq on a line indented past textwidth.** 84 spaces and `a`, `<C-v>gqgq_i<Tab>`: Neovim 85 spaces and [1,84], ours 88 and [1,87]. Only seen with indents wider than 79 (hypothesis: Neovim's stale w_virtcol, as the `s<Tab>` rule).

### Notes, not blocking

- **Comment leaders** (listed in src/keys/README). Counted: 867 of 3,000 sequences differ when half the lines start with a leader (`gq.py lead`, seed 11). What it means in use: `gqip` on `- first item / - second item / - third item` gives one line `- first item - second item - third item` (Neovim leaves the list alone), and on a two-line `//` comment the broken line loses its `//`. Markdown is one of Davy's two first languages, so this gap should be next in package 5, and Davy should know gq is not yet safe on lists and comments.
- `.SQL` in capitals is not SQL (same test as the colours, so they agree). Matters on Windows.
- One sqlfmt edit spans from the first to the last changed byte, so a format that changes the top and the bottom of a large file replaces everything between: marks there are unset and the undo step holds that text. Package 18's range, not this PR.
- Not gq, for package 5: CTRL-R of a register that holds a form feed drops it (`ipsum\x0csed.`, `y$A<C-r>"`). `gq(<C-w>gqgg` differs in the cursor (the CTRL-W g prefix).
- The sqlfluff question is answered by the author: Davy's hook is sqldiff.toml only.
