Reviewed at 4fc3dae (PR 57's head 5944342 merged in), against main c82e009,
on 2026-11-18. Judged from the diff, `CLAUDE.md` and my-nvim 695e3d7's
`lua/config/core/kitten.lua`, with Neovim 0.12.6. Repro files are in
`reviews/pr-59-repro/`.

**Verdict: changes requested.** The kitten matches my-nvim on every recorded

outside the grid on a one or two row screen, a wrong message after a file

## Findings to fix before merge

### 1. A read outside the grid on a screen of one or two rows

`kitten.c:155` reads `g->c[(r + 2) * g->cols + end - 3]` to place the "@@@".
With fewer than three rows `r` is 0 and row `r + 2` is not in the grid.
Nothing is written there (`grid_put` checks), but the byte read decides a
column.

- **measured**: `probe tiny` (every frame on every screen from 1 x 1 to
  6 x 18) stops with ASan's heap-buffer-overflow at the first size.
- **measured**: the real editor in a 2 x 3 terminal, `:w`:
  `small.py 2 3` ends with the same ASan report at `kitten.c:155` from
  `main.c:105`. At 2 x 20 the read is also outside the grid (cell 57 of 40)
  but lands in other live memory, so ASan is silent.

Neither test covers a screen under five rows. Fix: do not look past the
grid (for instance draw nothing when the three rows do not fit), with a test
and a plant.

### 2. After a non-ASCII file name the message has leftover characters

`probe msg 全角.md` shows the last row as `=^.^= saved 全角.mdmd`
(**measured**). The core draws `e->msg` one byte per cell (`grid_puts`,
`draw.c:441`), so the name takes 9 cells there; the kitten then paints the
same message again by character over 7 of them, and "md" is left behind.
With `é-ü.txt` it is `=^.^= saved é-ü.txtxt`.

The core's byte-wise message is on main already (any message with such a
name is wrong, the "written" one too), so the cause is not this PR's. But
the kitten's message is this PR's, and the recorded cases use these very
names for the float. Fix it where it is cheapest: the shared helper of
finding 4, used by the core for the message as well, and a test of the
message row with one of the non-ASCII names.

### 3. Under a taller command line the kitten is in the wrong place

The float's row is `g->rows - 2 - 3` and the message's is `g->rows - 1`.
kitten.lua uses `lines - cmdheight - 1 - 3`, and the core puts the message
on the command line's first row (`e->layout->height`).

- **measured**: `probe cmdheight` (one window, `core_resize` by -2, so the
  command line has three rows, on 10 x 40): the float covers the status
  line and the command line's first row, and afterwards the message is
  there twice, plain on row 7 and tinted on row 9.
- **measured**: Neovim with the same layout (`cmdheight.lua`) has the float
  on rows 3 to 5, above the status line.

No key reaches `core_resize` on this tree; PR 26 wires CTRL-W - and
`:resize`. Fix here or with the header change of finding 4, before or with
PR 26; the kitten needs the command line's row from the core.

### 4. Two helpers copy existing ones (Davy's rule, 2026-11-18)

- `width()` in `kitten.c` is `cells()` in `src/core/draw.c:178`, line for
  line.
- `put()` is the third writer of UTF-8 text into a row, after `text()` in
  `src/tools/pick.c:622` and the loop in `draw.c:231`. The PR says so and
  asks thread 0 for a shared one.

PR 57, the header round this PR waits for, is still open, and finding 2 is
fixed by the same helper. So the helper (UTF-8 text with a face into a row
up to a column, and the width of a string) should be in `grid.h` before this
merges, with the kitten, the picker and the core's message using it.

## Smaller points (not blocking)

- **Screens of 11 columns or fewer differ from Neovim** (**measured**, 1 run
  each): at 8 x 11 the last row is ` > ^ <  @@@` against Neovim's
  ` > ^ <   @@`, at 8 x 10 ` > ^ < @@@` against ` > ^ <   @`. There the
  float's first line wraps too. Not a width anyone edits in; say so in the
  comment or the PR's "Known" list.
- **Shorter code.** (a) `sum` and its copy can go: the message is the
  kitten's exactly when it starts with `=^.^= saved `, so twelve bytes of
  `e->msg` say it; the test's "another message" case would then use another
  text. (b) `Frame.text` is always `heart[0] != 0`. Both keep every
  requirement.
- **The new model has no plant.** `Pace_ok.cfg` has one in
  `tests/plants/win.txt`; `Kitten_ok.cfg` has none (the must-fail
  configurations show the model can fail, the plant shows `make specs`
  notices).
- **`loop_timer`'s result is ignored.** With all 16 timers taken the kitten
  would stay until a key. **Hypothesis**, not run: nothing on this tree uses
  more than a few.
- **The message is tinted only in normal mode.** The core also shows it in
  other modes that are not insert or command line; today there are none on
  this tree, so nothing to see yet.
- The macro rule (`reg_executing`) is open as the PR says.

## How to rerun

```
bash reviews/pr-59-repro/run.sh                 # probe: msg, cmdheight, pick, tiny, bench

```

`idle.py` keeps strace's log outside the file's directory: the editor
watches that directory, and a log written there wakes it for every line.
