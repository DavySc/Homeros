## Findings

### 1. The plant pins the fix as a whole, not its two guards (not blocking)

conform.py gained two guards: one for live cases, one for an entry's
example. The plant's example (`<Del>` alone) fails in the driver too, so
either guard alone catches it. **Measured**, 1 run each (`matrix.sh`):

| conform.py | PR's plant |
|---|---|
| as in the PR | caught |
| both guards out | NOT CAUGHT |
| live guard out | caught ("1 differ, 79 more are known") |
| example guard out | caught |

The third row is PR 32's finding itself (79 driver failures counted as
known), and the plant does not notice it coming back. Two plants replace
the one (commit before this report): the driver fails on Delete only when
more keys follow and otherwise ignores it (the example differs honestly,
live cases fail), and the driver fails on `Q`, which only the example
types. Measured, 1 run each: both caught at PR code; live guard out, the
first is NOT CAUGHT; example guard out, the second is NOT CAUGHT.

### 2. planted.sh reads a missing library as a catch (not blocking, older than this PR)

Found by accident, before the libraries were installed: every conform
plant, with the fix or without it, printed

    caught ... src/font/font.c:10:10: fatal error: ft2build.h: No such file or directory

The filter for build errors matches `file:line: error:` but not `fatal
error:`, and the word `error` then counts as the check's own failure. CI
has the libraries, so nothing is wrong there today, but it is the same
kind of false catch this PR closes. The follow-up commit adds `(fatal )?`
to the filter; measured, 1 run each: with freetype hidden
(`PKG_CONFIG_LIBDIR`) both plants now print FAILED OTHERWISE, and with the
libraries they are caught as before. The other 226 plants were not rerun
with that change here: the next PR's CI does that.

### 3. Notes, no action asked

- A driver that exits 0 and prints JSON without `lines` (`echo {}`) still
  counts as known under a matching rule (measured, `drivers.sh`).
  tests/conform_drv.c cannot do that: it prints `lines` on every path that
  returns 0.
- `known-crash.sh` prints "exit 0" on its last line because `$?` there is
  `tail`'s; make's "Error 1" above it is the real result.
- The PR text says exit 2 (make's code); conform.py itself exits 1.
