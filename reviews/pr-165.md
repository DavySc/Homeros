## Findings

### 1. `]d` `[d` `]D` `[D` hold the loop: every line times every diagnostic (blocking)

`next_diag()` (src/keys/normal.c) walks the lines from the cursor, and for each line computes `diag_pos()` (three tree lookups) of every diagnostic, twice for a candidate. Neovim groups the diagnostics by line once (`diagnostic_lines()`), so its walk is lines plus diagnostics.

Measured (optimized build, a diagnostic on each of the first N lines of a file of `int x;` lines, cursor ten lines below them, so `]d` wraps; the machine also ran `make check`):

| Lines | Diagnostics | Homeros `]d` | Neovim 0.12.6 `]d` |
|---|---|---|---|
| 1,000 | 100 | 12.9 to 18.5 ms (3 runs) | 0.6 to 0.9 ms (3 runs) |
| 5,000 | 30 | median 14.2 ms, 14.1 to 22.6 (5 runs) | not run |
| 20,000 | 50 | median 115.7 ms, 115.2 to 178.6 (5 runs) | not run |
| 100,000 | 100 | 1,607 to 1,683 ms (3 runs) | 0.6 to 1.9 ms (3 runs) |
| 100,000 | 1,000 | 33,140 to 34,474 ms (3 runs) | 1.2 to 3.1 ms (3 runs) |

`]D` and `[D` cost the same (1,568 and 1,661 ms; 36 and 35 s). A 5,000-line C file with 30 diagnostics already costs two frames. lsp.h keeps the diagnostics sorted by start (core's `diags_on()` in draw.c relies on it with a binary search), so one pass over the diagnostics finds the next one without walking lines.

Repro: `python3 reviews/pr-165-repro/mkcases.py diag DIR 100000 1000; fake DIR/cases.txt DIR @1010,0 ']d'` (build line in `run-plants.sh`'s link script: the Makefile's test line with `fake.c`).

### 2. The PR breaks two older plants (blocking)

`tools/planted.sh` prints BROKEN PLANT and fails for a plant whose text is no longer in the file once. Both applied on b1d6299 and do not on bdd2925:

- `tests/plants/keys.txt:74` "SPC maps other than SPC i s also run in Visual mode": `usable()`'s line changed.
- `tests/plants/tools-make.txt:6` "make: a write runs it with its buffer in no window": ` && buf() && shown()) run();` is now `... shown() && !M.list && !show(e, 0)) run();`.

### 3. C-] with several definitions takes another one than Neovim

The PR sorts the places by URI and position and opens the first. Neovim's `vim.lsp.tagfunc` gives the tags in the server's order, and C-] takes the first. Measured, same answer to both (m.c of four lines, z.h):

| Answer (in the server's order) | Neovim | PR |
|---|---|---|
| m.c 3,4 then m.c 1,4 | m.c 3,4 | m.c 1,4 |
| z.h 0,4 then m.c 2,4 | z.h 0,4 | m.c 2,4 |

The PR's own plant "C-] lists every definition" passes over this because the test accepts any column up to the first sorted place's. Related, not measured here beyond one run: with no definition Neovim says `E433: No tags file` and `E426: Tag not found: int`; the PR says "No locations found". If that is meant, the PR's table should say so.

### 4. The list opens with the cursor on its last entry

After `grr`, `gO` or several places from `gri`, the list's window has the cursor on the last line (clangd, 3 references: cursor line 2; Enter says "(3 of 3)"). Neovim's `botright copen` leaves it on the first entry (measured: 0,0). `put()` moves the cursor with `:make`'s output; a list should not follow.

### 5. The keys are thinly tested

The places and the diagnostic jumps are compared with Neovim case by case. The keys are not: the fake answers any request with the case's answer and never looks at what was asked, and the key part types only `SPC m a`, C-], C-o and `grr`. Of my 22 planted bugs 5 were caught and 16 were not; one (the same-buffer guard in `core_buf_enter`) I do not count, since `make conform` covers CTRL-O in one buffer and I ran only `test_lsp_locs`.

Not caught (each built and run against `test_lsp_locs`, which passed):

- keys.c: the cursor's position not sent (0 instead); `gri` and `grt` swapped; `gO` asking for references; no "No ... found" message.
- lsp.c: the position sent always the file's start; `references` without `includeDeclaration`; no `linkSupport` offered; a URI's `#fragment` kept; the drive form `file:///C:/x` not handled; an error answer reported as nothing found.
- normal.c: `]d` without `setpcmark()`; C-] without a server not beeping; the `to != got` stop gone (the generator avoids the case).
- make.c: names not made relative to the current directory; `M.list` never reset, so `:make` after a list is no longer re-run by a write; the file-alone place moving the cursor to line 0 (harmless today: the file opens at line 0 anyway).

The key part also depends on the seed. With seed 165 the first one-place case points at the cursor's own position; C-] then leaves no jump, so C-o goes one entry further back and `tests/test_lsp_locs.c:72` fails. Neovim does the same there (`nvim_same.lua`: C-o lands in the other file), so the editor is right and the check is wrong. With that case skipped the run ends in `CHECK(keyed[0] && keyed[1] && indented)` failing. The recorded trace passes, so nothing is red today, but a new recording can be.

The PR text says the plant results are "in a comment below"; the PR has no comment.

### 6. Two mechanisms written a second time

- **A file:// URI to a path.** `fname()` (src/lsp/lsp.c) decodes `%XX` and the drive form. `visit()` in src/infoview/infoview.c already decodes a file:// URI by its own loop (without the drive form). lsp.c owns the encoder (`uri()`), so the decoder belongs beside it behind lsp.h, the infoview calling it, with an owners.txt line. That needs thread 0 and package 14; this PR should at least export it and record the debt.
- **A name relative to the current directory.** `tools_locs()` calls `getcwd` and strips the prefix by hand; src/tools/pick.c has `path_rel()` and `P.cwd` for exactly that, in the same package. The new copy also tests only `/`, where pick.c uses `sep()`, so on Windows nothing would be stripped (not run on Windows).
- Smaller: the two-line loop that finds a document by URI is now in `lsp_send()` and in `located()`.

### 7. A place in a file that cannot be read is undefined behaviour

When the server names a file that is not open and cannot be loaded (deleted since it was indexed, say), `located()` leaves `data` NULL and calls `memcpy(l->text, b, len)` with `b` NULL and `len` 0. The sanitizer build stops: `src/lsp/lsp.c:1001:50: runtime error: null pointer passed as argument 2` (measured, 1 run: `mkcases.py defs DIR other`, delete `DIR/0/z.h`, `fake DIR/cases.txt DIR grr`). The PR's own plant "a file:// URI's %XX not decoded" is caught by this error, not by a comparison. No recorded case has a missing file.

## Not findings

- An entry of a buffer that was `:bd`'d: `enter_buffer` reloads it and buffers are only freed in `core_free`, so the jump list's pointers stay valid (read, not run).
- A server that dies before it answers: `lsp_send`'s callbacks get NULL and `located()` frees its request (read; ASan and LSan were clean over 2,300 cases).
- The buffer a place opens is named by its absolute path, where the file the user opened keeps the name typed. Worth a look when the status line shows it.
