# Review of PR 141: one SQL completion popup by the statement under the cursor (package 19)

Reviewed head `08e9d58d` (2 commits: thread 0's bundle `87b48cbd`, then the
package's change), base `6eba6830`, main `10d8b65e` at the time. Review
thread "Review SQL completion PR 141", 2026-11-23. Everything below is
**measured** (run here, counts given) unless it says otherwise.

## Verdict: changes requested

The design answers both of Davy's complaints: with his catalogue, snippets
rank below T-SQL's words (an exact name still wins), and the list follows
the statement (columns after `alias.`, tables after FROM, variables after
`@`). But it crashes on ordinary files (A), and it puts a parse of the whole
file on the key (B, C), against DESIGN.md's gate "frame ready after a key:
under 2 ms, p99".

## Blocking

**A. Heap use-after-free in `collect` (crash).** `fact()` and `flush()` pass
pointers into `pool.s` (`pool.s + tab`, `pool.s + CAND(*pairs, i).w`, `q`)
to `intern()` and `cand()`; `str_add` reallocs the pool and then copies from
the freed block (`str.c:24`), and `fact` runs `strlen(w)` on it after
`intern(of)`. ASan aborts:
- `reviews/pr-141-repro/uaf.sql` (one SELECT of 400 `t.column_number_i`),
  cursor after `where t.`, key `c`: 1 of 1 runs.
- a plain 20 KB T-SQL file (`real.sql` repeated), key `.` after an alias:
  1 of 1 runs, the pool's 1,024-byte block.
`test_snip`'s files never grow the pool, so the suite is green.

**B. Every key in a comment or a string parses the whole file.** `collect`
returns 0 there, `W.b` stays NULL, and the next key collects again. Per key,
`-O2`, 3 runs of the 6 keys of `select` (make check running beside it):

| file | in a comment | in a string | in a statement, keys 2 to 6 | `.txt`, no popup |
|---|---|---|---|---|
| 150 KB | 5.4 to 6.7 ms | 5.4 to 8.4 ms | 0.03 to 0.08 ms | |
| 700 KB | 25.0 to 40.7 ms | 25.8 to 39.3 ms | 0.03 to 0.07 ms | 0.002 to 0.006 ms |

**C. A word's first key costs a parse of the file.** 5 runs each, same
build: 1.7 to 2.5 ms at 30 KB, 6.0 to 6.7 ms at 150 KB, 26.5 to 33.1 ms at
700 KB (the PR says 1.1, 5.4 and 22; this machine was busy). About one key
in six starts a word, so the 2 ms p99 gate fails from about 30 KB up, and
Davy opens SQL files over 600 KB. The cost has to leave the key.

**G. The Windows build fails.** `make win` (in `make check`), clang for
Windows: `src/snip/snip.c:625: implicit conversion from 'unsigned long
long' to 'unsigned long' changes value from 14695981039346656037 to
2216829733 [-Werror,-Wconstant-conversion]`. `unsigned long` is 32 bits
there, so `hash()`'s 64-bit FNV constants do not fit. Dropping the hash
set (see Code) removes it.

## To fix with them

**D. `sqlfmt_units` returns some units when memory runs out** (thread 0
asked for 0). In `src/sqlfmt/sqlfmt.c` a failed `GROW(v, n, cap)` skips the
unit and does not set `oom`. Fresh processes, the N-th allocation failing:
264 of 265 units (N = 15, 16), 1,288 of 1,289; every allocation from the
N-th failing: 256 of 265, and 256, 512, 1,024 of 1,289. A failure in lex or
parse does give 0 (N = 1 to 14). The file is thread 0's bundle.

**E. Out of memory inside `collect` crashes.** With A patched locally, one
failed allocation during the key (N = 1 to 130): heap-buffer-overflow in
`flush`'s `strcasecmp` (2 values of N; 12 when all later ones fail) and in
`hash` (2): `intern`'s -1 is stored as an offset and read at `pool.s - 1`.
A `.txt` buffer survives the same failures (0 crashes). The PR's text says
the popup "just has no statement context".

**F. The cached list outlives the word.** Backspace to an empty word keeps
`W`: `SET ` + `s`, BS, `@b` shows nothing (`@b` alone: `@batch_size`);
`@`, BS, `s` offers `@@spid @start_date @@servername @@servicename`.

## Smaller, measured on `real.sql` with Davy's catalogue

- `[Some Col]` is listed and inserted without its brackets: `m.Some Col`.
- The same column once per table in the statement: `total` 3 times,
  `customer_id` 4 times after `AND cu`.
- `FROM @`: nothing, though `@ids` is a table variable (the PR lists it).
- `join d` offers `dbo` as a table; after `dbo.` nothing.
- `DELETE f` offers nothing (FROM is a word, the context is tables only).
- Rare words before common ones by length: `sel` gives `self select
  selective`; `s` puts `select` past the 25th place. Letters until the word
  is first, 45 common words: median 3 (select 4, where 4, values 6 of 6,
  procedure 5). Not blocking; a short list of common words at a better
  `pri` would do.
- After `@` the variables are mixed with the 30-odd `@@` functions by
  length.
