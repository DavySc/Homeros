## Findings

1. **Blocking: two plants no longer apply.** `tests/plants/kitten.txt`
   lines 11 ("a second save restarts it") and 12 ("plays for another
   buffer's save") replace the whole old line
   `if (!off && b == e->buf && !(frame >= 0 && for_buf == b)) kitten_paw(e);`,
   which the PR rewrote. `tools/planted.sh` prints `BROKEN PLANT` for both
   and exits 1 (measured). CI did not show it: its shards 1 to 3 of 8 were
   cancelled at the 90 minute limit. A fix that keeps both plants and
   survives the next edit of that line is to replace only the part each plant
   removes (`reviews/pr-99-repro/kitten-plants.diff`):

   ```
   ...~src/kitten/kitten.c~ && !(frame >= 0 && for_buf == b)) kitten_paw(e);~) kitten_paw(e);
   ...~src/kitten/kitten.c~ && b == e->buf && !(frame~ && !(frame
   ```

   With these, all 19 kitten test plants are caught (lines 187 and 192 of
   tests/test_kitten.c catch the two).

2. **`@:` that repeats `:w` shows no kitten; kitten.lua shows one**
   (measured: 4 of 4 probe runs; and `reg_executing()` is `""` during `@:` in
   Neovim 0.12). Cause: `do_execreg` in src/keys/ops.c sets
   `E->ks.executing = regname` in the `':'` branch (line 1636) and the `'.'`
   branch (line 1644); Neovim's `do_execreg` sets `reg_executing` only in its
   last branch, for a named register. Before this PR `@:` played the kitten
   as Neovim does, so this PR makes the keys module's difference visible
   here; it also reaches the other readers of the flag (the yank flash in
   `op_yank`, `q` at src/keys/normal.c:954). The kitten's line is the right translation;
   the fix is two deleted lines in package 5 with a plant, not a special case
   here. Not blocking: the six macro cases above now match, one rare case
   stops matching. `'.'`: hypothesis from Neovim's source, not measured (my
   InsertCharPre probe did not fire for `@.`).

3. Simplicity and duplication: nothing to flag. One condition added to an
   existing test in one line; no new function; `make dupes` passed. The
   comment names `reg_executing()`, as CLAUDE.md asks for copied rules.

4. Test and plant: the test saves with `executing` set and checks that the
   kitten's rows stay blank; the state before it is blank (the case above it
   ends in `CHECK(gone())`), so the check can only pass by the new condition.
   The plant removes the condition and applies exactly once.
