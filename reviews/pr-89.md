## Notes (none blocking)

1. **Frames come 351 ms apart, not 350** (measured above): each timer starts at the draw, not at the previous tick. Over 300 s that is 3 frames fewer than splash.lua's repeating timer. Not visible; it is the price of the rule that the draw arms.
2. **Two choices that are Davy's taste, not splash.lua's.** The shimmer is on the terminal's frame and the name, where splash.lua shimmers the cat's outline; and the frog blinks half a cycle after the cat. Both are recorded from Neovim through dash.py's own Lua, which applies splash.lua's rules to the picture (splash.lua's cat is generated, so it cannot be called directly). The oracle therefore checks dash.c against the same author's Lua; the rules themselves I compared with splash.lua by reading (table above).
3. **`FACE_DASHBOARD_TERMINAL` is dead** after this PR (the PR says so). Thread 0 should delete it with its theme row and SGR row: "delete before you add".
4. **DESIGN.md's "New approaches" row** now names dash.c but its evidence cell still lists only `test_kitten` and `test_kitten_win`. Add `test_tools_dash`. There is no Windows run of the animation (`make win` only links it); the timer it uses is the one `test_kitten_win` runs.
5. **Hidden window on a real compositor**: not run by me or the author; the claim rests on Kitten.tla, the unit test with no draws, and reading `main.c`.
6. `loop_timer`'s result is ignored: with the timer table full the picture stands still and nothing else happens. The kitten does the same.
