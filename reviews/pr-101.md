## What the PR does

Folds five mechanisms the audit (`research/duplicate-mechanisms.md` in project files) found
built more than once: UTF-8 encoding (`uni_put`), splitting a child's output into lines
(`str_lines`), putting the cursor at a line and column (`core_goto`), reading a run of digits
(`match_num`), and the save path (`core_write` calls `keys_write_pre` first and `lsp_saved`
after). Source and headers against main: 21 files, 119 lines in, 115 out; tests and plants 61 in,
5 out.

## Findings

### 1. Two copies of the folded mechanisms were left (fixed in 57f9787)

Found at e7a4eeb by searching for the patterns the PR removed:

- `src/tools/oil.c:259` held the same saturating digit loop as `match_num`, in the same package.
- `src/infoview/serve/serve.c:442` held a third copy of the line splitter (byte by byte into a
  `Str`, then `from_editor`), in a program that already links `src/str/str.c`.

**Measured** (1 run each): with both folded in a scratch tree (`pr-101-repro/leftover-folds.diff`,
7 lines in, 9 out) `test_tools_oil` (405 cases, 0 differ), `test_infoview` and `make dupes` pass.
The author applied the same folds in 57f9787 and aimed the "oil: a long id overflows" plant at
`match_num`'s line with `fuzz_tools_oil`.

### 2. A fuzzer did not compile on the first two heads (fixed in aad695a)

`tests/fuzz_infoview_call.c` called `from_child` with its old two arguments. `make compilers`
does not build fuzzers, so only `make fuzz` shows it; the author's CI run and local check hit it
and aad695a fixes the call. **Measured**: on aad695a `fuzz_infoview_call` did 1,168,147 runs in
31 s inside my full check.

### 3. A header comment edited outside thread 0 (settled)

57f9787 changes the comment on `keys_write_pre` in `include/keys.h` in the author's own commit.
The author reports thread 0 agreed the wording at 13:26 UTC (reported to me, not read from thread
0 itself). The other header changes are exactly thread 0's `cleanup.bundle` (45338ed on fabfbf8):
**measured**, `git diff 45338ed e7a4eeb -- include` is empty.

### Notes, not blocking

- **didSave is sent whether or not the server asked for it.** Neovim sends it only when the
  server's `textDocumentSync.save` is set. **Measured** (1 run, `pr-101-repro/didsave.py`): the
  real Lean 4.35 server advertises `"save": {"includeText": true}`, takes three `didSave` without
  text, reports no error and still answers a hover. A server that does not advertise `save` is
  untested (**hypothesis**: it ignores the notification, as the protocol lets it). The next
  language server added (slang-server for SystemVerilog) should be checked, or `lsp_saved` should
  read the capability.
- **The 4 KB fix is real but hard to see.** rg runs with `--max-columns=500`, so a grep line
  longer than 4 KB needs a path of several KB. `test_str` covers long lines in `str_lines` itself.
- **git's cursor line now takes `core_set_want`** where it set `want = 0`. They differ only on a
  line that starts with a tab or wide character; the status buffer's lines start with a diff
  marker or a section name. Not reproduced as a visible difference.
- **`match_num` on malformed rg output:** `file NUL :5:text` (no line digits) used to give line
  0 and now drops the line. rg never prints that.
- **PR 94 (terminal)** adds a global `utf8_put` and must switch to `uni_put` (it carries the same
  commit fabfbf8). Whichever lands second resolves `pick.c`'s `edit()`.
