## Blocking

**B1. The goals window never draws its last line; one-line states draw nothing.** `src/lsp/lsp.c:878` (`commit`). The text has no final newline, and core counts newline-terminated lines. `run.sh draw2`: buffer `case c\nh : T\n⊢ G` (2 lines), drawn rows `case c`, `h : T`, `~`: the `⊢` line is missing. `run.sh draw1`: buffer `No goals.` (0 lines), window all `~`. Same for "Processing file...", "Goals accomplished 🎉" and the tombstone. The test compares `text_read` only, never `core_lines` or the drawn grid. Fix: end with `\n`; test what is drawn; plant.

**B2. Crash: a goals-window cursor past the new end.** `src/lsp/lsp.c:876-880`. `commit` replaces the text but leaves the windows' `line`, `col`, `top`. `run.sh cursor`: 12 goals shown, go to the goals window, `G` (line 46), back, `j` (answer "No goals.") gives `current line 18446744073709551615 of core_lines 0`, then `AddressSanitizer: requested allocation size 0xfffffffffffffff7` in `core_line` (`src/core/core.c:56`). `git_fill` (`src/git/status.c:376-386`) does this same operation and does clamp. Fix: see S3.

**B3. A failing `$/lean/rpc/connect` is retried without bound.** `src/lsp/lsp.c:933-940` (`on_sess`; also `late`, 927). Any answer, an error too, sets `G.want = 1` and calls `gask()`, so connect goes out again at once; a server answering -32900 to every call loops the same way. `run.sh flood` (connect answered -32603): 27,946 and 74,675 connect requests in 1.5 s with no key (2 runs); the window stays on "Processing file...". Fix: no retry on a connect error until the cursor moves or the server speaks; at most one reconnect per question after -32900; plant.

## Should fix

**S1. `severity` above 4 indexes past `sev[4]`.** `lsp.c:872` (face at 867); line 587 clamps only below. `run.sh sev` (`"severity":7`): `src/lsp/lsp.c:872:15: runtime error: index 6 out of bounds for type 'char *[4]'`. Fix: `if (g.sev < 1 || g.sev > 4) g.sev = 1;` at 587.

**S2. Removing `LSP_GOAL` breaks `src/infoview/oracle/drive.c`** (`drive.c:30:37: error: 'LSP_GOAL' undeclared`, with `gcc -std=c17 -D_DEFAULT_SOURCE -Iinclude -fsyntax-only`). It is not built by make, but its README still says to build it. Port it or delete it (package 14's directory: ask that thread).

**S3. Two mechanisms already exist in `src/git/status.c`** (each under 50 tokens, so `make dupes` passes): `gbuf()` (`lsp.c:822`) is `git_buf()` (`status.c:359`), and the end of `commit` (`lsp.c:877-880`) is `git_fill`'s body (`status.c:381-385`) minus the cursor reset whose absence is B2. One "replace a scratch buffer's text and clamp its windows" helper, through thread 0, called by both, fixes B2 and the copy (one solution per problem).

**S4. `nonumber` does nothing on this tree** (`lsp.c:984`): nothing reads `Buf.nonumber`; `run.sh draw` shows relative numbers in the goals window. The test checks only that the flag is set. Either core's support lands first, or the PR body should not claim it.

**S5. Buffer rewritten more often than the view changes.** `handle` runs `ranges` twice per `publishDiagnostics` (`lsp.c:627`), each ending in `gpoke` (`commit` + `gask`): 11 full rewrites for 10 messages in `run.sh draw` (measured, 1 run, with a temporary counter). Fix: one `gpoke` per message, from `handle`; skip `commit` when the text is unchanged.
