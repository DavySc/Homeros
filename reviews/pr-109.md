## Why the old test was flaky, and why the new one is not

Old: `bridge_free`, wait for the old child's file to vanish, then `bridge_open`. The old child's end
(stream 0) could reach `out()` before the new child was spawned, where the planted bug does nothing.

New: `bridge_open` right after `bridge_free` with no loop turn between, so the old end always comes
after the successor exists. With the plant it then fails one of two ways (both seen, below):
- the end arrives before the new child's redirect line: `proc = -1` is the new child's, so the page is
  never opened (`count(o, "\n") == 3` fails, line 576);
- it arrives after: the new child's state is wiped, so the extra `bridge_open` spawns a third child
  and the fourth opened line differs from the third (line 591).
