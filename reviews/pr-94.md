## Findings

### 1. Ctrl+Z in the terminal never reaches the shell (blocking; measured on Wayland, Windows by reading)

`src/main.c` takes `KEY_CTRL_Z` in normal mode and calls `b->suspend()` before `keys_input`, so `tools_key` never sees the key. On Wayland `wl_suspend` does nothing, so the key just disappears. On Windows `win_suspend` minimizes the editor window. This is a **hypothesis from reading**: the same main.c branch, but I did not run it on Windows.

Repro (`reviews/pr-94-repro/ctrlz.sh`): headless sway, the editor, Ctrl+., `sleep 300` Enter, Ctrl+Z, `jobs; echo MARK` Enter, then grim.
- In **3 of 3 runs** sleep was still running and the next line went to it as input (`ctrlz-lost.png`). Bash never printed a "Stopped" job.
- The control run replaces Ctrl+Z with Ctrl+C, and there the shell gets ^C and runs MARK (`ctrlc-control.png`). So the harness does deliver Control keys.

Davy's Ghostty and snacks both give Ctrl+Z to the shell, and so does Neovim's :terminal. The fix lives in main.c, which is thread 0's. One option: suspend only when the terminal is closed, via a `tools_*` query or by letting `tools_key` see the key first. The author should ask thread 0. A test should send Ctrl+Z through main's path and look for "Stopped", with a plant on the fix.

### 3. The colour-slot search costs about half of term_draw (not blocking; measured)

`face_of` scans the slots linearly for every cell. `reviews/pr-94-repro/bench_term.c` measures core_draw + tools_draw on an unchanged 50x200 screen that a program painted with N 24-bit colours, as the median of 201 draws. I ran 5 alternating runs per side, during a parallel `make check`, so the numbers are noisy but the ranges do not overlap:

| N colours | PR (ms, median of runs, range) | with a 4096-entry memo (ms) |
|---|---|---|
| 100 | 0.523 (0.519-0.573) | 0.281 (0.275-0.329) |
| 900 | 2.272 (2.260-3.345) | 2.194 (2.170-2.226): no measurable difference |
| 5000 | 3.740 (3.612-3.963) | 3.722 (3.617-4.642): no measurable difference |

The memo is 6 lines: a direct-mapped hash of the Face to its last slot, checked with memcmp, so no stale entry can be wrong. Neovim's attr table is a hash too (`get_attr_entry`). For the common case (under 100 colours) it cuts about 0.24 ms per drawn frame. It does not help a whole-screen gradient. That cost is elsewhere, partly libghostty's own row walk, and I did not profile it further. Since speed is Davy's first priority I recommend the memo, but it is the author's call.

### 4. Two zig command lines for one library (minor)

`.github/workflows/check.yml`'s windows job repeats ghostty.nix's `zig build -Demit-lib-vt -Doptimize=ReleaseFast -Dcpu=baseline -Dtarget=…` with its own fetch of the source. If one changes and the other doesn't, the Windows lib quietly drifts from the Linux one. A shared script, or reading the flags out of ghostty.nix the way the job already reads the revision, would make one copy. Not blocking, because the runner has no nix.

### 5. ConPTY's last output (hypothesis, not blocking)

`report()` closes our pipe ends and then calls ClosePseudoConsole. Microsoft's ConPTY guidance is to call ClosePseudoConsole while still draining the output pipe, so conhost flushes its last frame. The test's comment blames Windows ("drops what a child writes just before it exits"). That may come from this order instead. It doesn't matter for the terminal, because exit closes the float. It would matter if `:make` or another job ever ran through proc_pty. I could not test this: Wine has no real ConPTY.

## Checked and fine

- **Linux PTY:** posix_openpt, then the slave opened after `POSIX_SPAWN_SETSID`, which is glibc's order: setsid before the file actions. That gives a controlling tty, confirmed by test_loop's /dev/tty case. The master is dup'd for the two ends, FD_CLOEXEC is set, and the env copy is freed (my leak plant was caught). Sharing proc_start through timer.c leaves no duplicated code, and `make dupes` passes.
- **Windows:** STARTUPINFOEX with the NULL std handles, `bInheritHandles` false for a pty, pipes for stdin and stdout only, and the pseudoconsole closed on failure and at report. It is green on real Windows in CI.
- **The slot reuse rule** ("not drawn in this frame or the shown one") holds in my reading. The test's `held[]` check catches both plants against it. Slot reuse cannot create a duplicate, because a slot is only reused when no slot matches.
- **The headers:** `Cell.face` became 16 bits and `faces[]` writable with 1024 slots, with the measurements stated in grid.h. `uni_put` has a proved contract, and the picker and terminal share it instead of encoding UTF-8 themselves.
- **ASan fix:** zig's compiler_rt and UBSan symbols are localized in the Linux .a. The PR reports the wl clipboard plant caught again (1 run). It is not one of this PR's plants, so I did not re-run it; CI shards cover it.
- The shell choice is still owed: it folds with `:make` once both have landed (terminal-libghostty memory). Not counted here.
