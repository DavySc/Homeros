## Findings

### 1. `ATTR_GUIDE` has the value of the Wayland backend's private `ATTR_PRE` (blocking)

`src/wl/wl.c:37` has `ATTR_PRE = ATTR_REV + 1` ("backend-private, after grid.h's attrs"). The PR adds `ATTR_GUIDE` after `ATTR_REV`, so both are 3. A guide cell is drawn as a preedit: underlined across the whole cell.

```
$ pr-57-repro/guide_underline.sh /home/claude/pr57n
ATTR_PRE=3 ATTR_GUIDE=3; underline pixels: ATTR_NONE cell 0, ATTR_GUIDE cell 10 of 10
```

**measured**, 2 runs. Nothing sets `ATTR_GUIDE` yet, so nothing on screen is wrong today, but the core package will set it from this header. Fix: `ATTR_PRE = ATTR_GUIDE + 1` (one token). The random frames in `test_grid_diff.c` still draw attributes with `rnd(3)`, so no check sees attribute 3 at all.

### 2. The background layer in the Wayland and Windows backends has no check (blocking under CLAUDE.md's plant rule)

The contract says all three backends must read `Cell.bg`. Only the terminal's read is tested. Removing it from the other two passes their checks:

```
NOT CAUGHT    rev: wl ignores the background layer   (make test TESTS=wl passed)
NOT CAUGHT    rev: wl row hash ignores the background layer   (make test TESTS=wl passed)
NOT CAUGHT    rev: win ignores the background layer   (make win WIN=win passed)
```

Reproduce: `REPO=<worktree> PLANTS=pr-57-repro/my-plants.txt bash pr-57-repro/my-planted.sh`. **measured**, 1 run. The code itself is right for Wayland (`wl_layer.sh`: a `comment.todo` cell under the cursor-line layer has pixel `2a2b3c`; measured, 1 run); it is the check and its plants that are missing. `test_win.c` already has a face-background case to extend; the PR only renamed that plant's text.

### 4. `AttachConsole` throws away a redirected stdout and stderr; the lines have no check (not blocking today, fix before a GUI-subsystem build ships)

`src/main.c` reopens `CONOUT$` whenever the attach succeeds, without looking at whether the handles were already valid. The snippet alone, built both ways with zig and run from a Wine `cmd` console:

```
$ pr-57-repro/attach.sh          (cmd /c "a.exe 2> err.txt")
pr    console  redirected stderr file: 'usage: homeros [-t] FILE'   console: ''
pr    windows  redirected stderr file: ''                           console: 'usage: homeros [-t] FILE'
base  console  redirected stderr file: 'usage: homeros [-t] FILE'   console: ''
base  windows  redirected stderr file: 'usage: homeros [-t] FILE'   console: ''
```

**measured**, 1 run. Without redirection the PR does what it promises (GUI build: usage reaches the console; base GUI build: nothing; console build unchanged; measured, 1 run). So:

- The console build is not regressed: the attach fails there and nothing is reopened.
- A GUI-subsystem build loses `2> file` and pipes, which is how a script or a test would capture the message. Fix: reopen a stream only when its standard handle is invalid.
- `-t` on Windows cannot be tested: the Makefile's Windows build leaves out the terminal ("no Windows half yet"), and the PR attaches only output, not `CONIN$`. **hypothesis**: `-t` in a GUI-subsystem build would have no input.
- No test builds `main.c` for Windows beyond `wincc`'s compile, and no plant covers these lines. The repo has no GUI-subsystem link (`grep -n mwindows\|subsystem Makefile src` is empty), so today the lines never take effect.

### The row hash without the layer

The author's claim holds. In `wl_present` the hash only picks the move `k`; what is drawn comes from `span`, which compares cells with `grid_cell_eq`, layer included, against the row the pixels were copied from.

I added a block to a scratch copy of `tests/test_wl.c` (`pr-57-repro/wl_scroll_block.c`, inserted before "a row back as it was two frames ago"): 120 frames at 36 by 128 cells where the text scrolls by 1 to 3 rows either way, the cursor line's layer stays on its screen row or moves, and heading bars move with the text. Each frame's screenshot from incremental drawing is compared with a whole redraw of the same grid.

```
REVIEWER: 120 frames (59 with a scroll, 36x128 cells), 0 differ from a whole redraw
```

- With `&& a->bg == b->bg` removed from `grid_cell_eq`, the same block reports 118 of 120 frames differing, so the check can fail (`wl_scroll_planted.log`).
- A counter in `wl_present` shows the row move is really taken: presents that copied rows rose from 9 to 96 over the run (`wl_scroll_shift.log`). The test's own loop has at most 20 scroll frames, so most of the rest come from this block.

**measured**, 1 run each. Leaving the layer out of the hash is also the better choice, not only a harmless one: with it in, a scroll under a fixed cursor line would change that row's hash and the move would be found less often.
