## Findings

1. **The bound was the only check that a successful `proc_wait` returns promptly** (not blocking). The PR calls it redundant. For the slot bug that is right (both plants are still caught). But with `if (!r) poll(NULL, 0, 700);` before `proc_wait`'s return, main's `test_loop.c` fails at line 539 on `ms() - t0 < 500`, and the PR's passes; the same plant in `win.c` (`Sleep(700)`) passes the PR's `test_loop_win.c` (**measured**, 1 run each; main's Windows test with this plant was not run). The other time bounds in `waits()` are on killed waits only. I do not ask for the bound back: a wall-clock ceiling is what flaked, and no code path in `proc_wait` can add such a delay today. If package 10 wants the property held, a CPU-free way is to count `loop_once` calls or compare against a generous multiple, in its own PR. The PR text could say "redundant for the slot check".
2. **Least code**: the new test is 11 lines, one loop over the three names, reusing the fake formatter and `text()`. I found nothing shorter that still names each extension. `t0` in both `waits()` is still used above, so no dead variable is left; both compilers agree.
3. The two blank-line deletions in `src/lsp/bench/` change nothing else (diff read).
