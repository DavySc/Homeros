## Findings

### 1. Linux: what the opener starts inherits the editor's pipes (thread 0's `proc_open`)

`proc_open` starts `xdg-open` through `proc_spawn`, so its stdout and stderr
are pipes to the editor and SIGPIPE is at its default (loop.c resets it for
children). Where `xdg-open` starts the browser itself (no desktop
environment to hand it to, as under Hyprland, and no browser running yet),
the browser holds those pipes; when the editor exits, its next line to
stderr gets SIGPIPE. On main the infoview's child started the opener with
`/dev/null`, so this is new for `\w`; git's `SPC g B` had it already.

- measured, 3 of 3: with a stand-in browser that writes a line to stderr
  every 0.2 s, the browser dies when the editor exits
  (`sh reviews/pr-138-repro/browser.sh pr`); with main's child it lives on,
  3 of 3 (`browser.sh main SERVE`).
- measured, 3 of 3: real Chromium (headless, `--enable-logging=stderr`)
  survives, because it ignores SIGPIPE. So the damage is limited to programs
  that do not; **hypothesis**: Firefox survives as well.
- Also while the browser lives, one of the loop's 32 process slots stays
  taken and the editor reads the browser's log lines only to drop them.
- Fix, measured 3 of 3 (the stand-in lives on): `reviews/pr-138-repro/fix.diff`,
  one line, the opener's output to `/dev/null`. It is thread 0's code.

### 2. Three parts of the Windows wait have no test that fails without them

"A check you have never seen fail proves nothing." I planted five bugs in the
Windows half (`reviews/pr-138-repro/plants.txt`) and ran them under Wine
(`wineplants.sh`) and on Windows itself (`winplants.sh`, one job each, run
45270561529):

| Plant | Wine | Windows itself |
|---|---|---|
| PR's: pipes synchronous | caught | caught |
| PR's: the event never reset | caught | **not caught** |
| PR's: blocking write to the editor | caught | caught |
| mine: one send per turn (`while` to `if`) | **not caught** | **not caught** |
| mine: the event without `FD_WRITE` | **not caught** | **not caught** |
| mine: no zero-byte read (`f[0].revents = POLLIN`) | caught | caught |
| mine: the redirect file left at the end | caught | caught |
| mine: `ResetEvent` after `WSAPoll` (a wake between them is lost) | caught 1 of 3 | **not caught** (1 run) |

(all measured; one run each unless said.)

The PR's description says the partial-send and `FD_WRITE` path "is tested
only on real Windows, in CI's windows job". Measured: it is not tested there
either; the 32 MB late read passes with the send loop cut to one send and
with `FD_WRITE` out of the mask, presumably because something else always
wakes the loop in that test (**hypothesis**). So either these two are not
needed and go (the shorter code wins), or a test must stall without them: a
page that reads late while the editor is silent and no timer is due, with a
time bound, and a plant for each in `tests/plants/infoview.txt`.

### 3. The Windows wait is a timing question without a model

`io_wait` is wait, `ResetEvent`, then `WSAPoll(0)`; the order is what keeps a
wake from being lost, and swapping the two is caught only by luck (row 8
above). CLAUDE.md asks for a TLA+ model for timing questions, with the
property stated first and a broken variant that fails. `design/specs/` has
`Infoview.tla` for the page's stream, nothing for this wait. Asked: a small
model (event set by the system at any time; wait, reset, poll; the edge-
triggered `FD_WRITE` re-armed only by a send that would block; the two APCs)
with "no ready socket or pipe waits forever" and the broken variants reset
after poll, one send per turn and no `FD_WRITE`. It would also settle
finding 2's question of what is needed.

### 4. Nothing tests the editor's half on Windows

`tests/test_infoview_win.c` drives the child directly. `infoview.c` on
Windows (the exe's name, `root()`, reading the file's name, `browse()`) and
`proc_open`'s `explorer` branch run in no test, under Wine or in CI.
One thing there I could not settle: the child writes
`%TEMP%` + `/` + `homeros-infoview-<hex>.html`, so `explorer` is given a path
with both kinds of slash, and `proc_start` starts it with `SW_HIDE`.
**Hypothesis, not measured**: Explorer opens such a path as it does one with
backslashes. My probe for it (`reviews/pr-138-repro/explorer.c`: a file type
whose handler records what it was given) never finished on the hosted runner
in 3 tries (Explorer on a runner without a desktop session hangs the job and
its log is lost), so this needs either a run on a Windows machine with a
desktop or the separator made `\` on Windows so the question does not arise.
Asked: the second, plus a test of `browse()` on Windows with a stand-in
opener, as `tests/test_infoview.c` has on Linux.

### 5. Smaller

- Linux plants of mine (`plants-linux.txt`, `make test TESTS=infoview`, 1 run
  each, measured): the redirect file readable by all, a second `\w` opening
  no browser, and the browser opened before the child named its file are
  caught. **Not caught**: "what the editor's pipe did not take is dropped"
  and "a blocking write to the editor on Linux". The Windows test covers a
  busy editor; the Linux half of `to_ed` has no test that fails.
- `624f71b8` (package 14's thread) edits `src/git/keys.c`, package 17's
  directory, to share `tracked()`. The change is right and `make dupes` asked
  for it; the report only records that package 17's agreement is not in the
  PR.
- The PR's plant "the event never reset" is caught under Wine and not on
  Windows itself (table above). Plants run under Wine, so the check holds;
  it shows the test sees a spinning child only by Wine's starvation.
- Not this PR's: `getenv` returns the ANSI code page on Windows, so a profile
  path outside it would break `%TEMP%` and `%LOCALAPPDATA%` here as elsewhere
  in the code.

## What is good

longer on a command line; the redirect file made `O_EXCL` 0600 and removed at

`safe()` is a whitelist, so a backslash cannot leave ROOT; the flaky plant in
`test_infoview` fixed properly, by ordering and not by a sleep.
