## Requested changes

### 1. `opmarks()` loses an insert's `']` when an undo ran inside the same Insert

`G i cd CTRL-O u ef Esc` then `` `] ``: ours line 8 column 0, Neovim line 8 column 2 (`cases.txt` lines 9 and 10).

Cause: `opmarks()` runs only at the start of a Normal command and lets the core's change win. The undo sets the buffer's mark, the insert then sets `b_op_end` with no Normal command between, and at the next command the older value (the undo's) overwrites the newer one. "What changed since the last meeting wins" cannot order two changes inside one interval.

The same shape looks reachable when the buffer changes without a Normal command between an operator and the switch (a picker's Enter): the first buffer's `'[` would be written into the second. **Hypothesis**, not run.

A rule with no guessing would be simpler: the keys are the writer, and the one place the core writes (`core_undo`) is followed by a read. Then `seen` and `had` go. Your call how; the case above must pass, and it needs a test and a plant. My plant that removes the core-to-keys half of `opmarks()` is caught by nothing (`make test TESTS=keys_ex` and the conform replay both pass), so today that half has no check at all, though `x u` then `` `[ `` already works and agrees with Neovim.

### 2. `']` after a charwise yank whose end is exclusive at column 0

| keys (on the test's text) | ours | Neovim |
|---|---|---|
| `j v j y` then `` `] `` (the area ends on the empty line 3) | line 4, col 0 | line 3, col 0 |
| `j y 0` then `` `] `` | line 2, col 0 | line 1, col 11 |
| `j j y l` then `` `] `` (yl on an empty line) | line 3, col 0 | line 2, col 7 |

Neovim steps back one character across the line break (it is `decl()`); `ops.c:325` only steps back when `col > 0`. Measured in Neovim on multi-byte text too (`marks.vim`): the mark lands on the last character's first byte.

This is the line above the PR's yank flash fix and it feeds the same area: after `j v j y` on test_keys_flash's text `ks.yank` ends at line 3 column 0 (0-based), the `x` of the line after the empty one, which was not yanked. So the flash shows one character too many there.

### 3. `~` and `r{char}` do not set `'[` and `']`

`~` then `` `[ ``: ours E20, Neovim goes to line 1 column 0. `y j r x` then `` `] ``: ours the yank's old mark (line 2), Neovim line 1 column 0. `r` Enter is right. Neovim's n_swapchar() and nv_replace() set both marks. Please add `~` and `rx` to the test alphabet with the fix.

### 4. `gv` after `m<` alone selects, and the next operator changes text

`j m< g v d`: ours deletes from line 1 to the mark; Neovim does nothing (`gv` needs both ends). New in this PR, since `m<` now sets the mark. `nv_gv_cmd()` checks only `'<`.

### 5. `:'` followed by Enter says E78

Neovim says nothing (`lone-quote-gv.vim`: v:errmsg stays empty). Main said E20, so this was already different; it changed shape here, and it is one line in `address()`.
