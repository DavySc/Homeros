## What the editor needs (measured)

The status buffer's content comes from 5 processes: `git --no-optional-locks status --porcelain=v2 -z --branch`, `log -10`, `diff`, `diff --cached`, `stash list`. 5 runs: 10.5 to 12.6 ms for all five.

Staging one hunk = `git apply --cached` with the hunk as a patch; unstaging = the same with `-R`. 5 runs each: stage 3.6 to 5.4 ms, unstage 3.6 to 4.0 ms.

A stale hunk is refused by git itself: after the hunk was staged elsewhere, applying it again fails with "patch does not apply" (rc 1, 1 run). So git's own context check is what makes "acts on what the user saw" hold; the editor does not need its own lock or version check for hunks.

Plain `git status` opens `.git/index.lock` to refresh the index (strace: 1 open with `.git/index.lock` present); with `--no-optional-locks` it opens it 0 times. Reads therefore use `--no-optional-locks`, so a refresh never fights a `git` running in Davy's terminal.

## Timing model (proved for the bounds, TLC)

`specs/Git.tla`: properties NoLock (two index writers never run at once), ActsOnSeen (a write applies only to the state the user saw), Truthful (once activity stops, the buffer shows the repository, outside changes included). `Git_ok` passes (MaxOps 6: 401 distinct states). `Git_parallel` fails NoLock, `Git_blind` fails ActsOnSeen, `Git_nowatch` fails Truthful.
