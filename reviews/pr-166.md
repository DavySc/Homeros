## Findings

### 1. Blocking: SPC 5 and a letter no frame has runs `5{letter}` on the text (measured)

`map()` enters a frame only when one has the letter; any other key falls
through to "no map matches", so Space runs as a motion and `5x` as typed.
Probe, two frames a and b, text `abcb`, cursor at the start: `SPC 5 x` leaves
`a` (Space moved one right, `5x` deleted three). By the same path `SPC 5 u`
undoes five changes, `SPC 5 p` puts five times, and `SPC 5 d`, `c`, `y`
wait for a motion with a count of 5 (`SPC 5 q` left the editor waiting:
`ks.pending` set).

The fall-through itself is main's (Neovim's vgetorpeek(), on purpose), but
before this PR no SPC 5 key was a letter that comes and goes. Now the letter
of a frame closed a moment ago is the likeliest slip there is, and it
changes the buffer. SPC 5 m with no such frame beeps, SPC 5 n with a taken
letter beeps: SPC 5 {letter} with no such frame should beep and do nothing
else.

`reviews/pr-166-repro/beep-sketch.diff` is one way (15 lines in, 11 out): a
`frame_letter(k)` both the jump and `frame_key()` call, and the jump beeps
when no frame has the letter. With it the probe's `SPC 5 x` case leaves the
text, and `make test TESTS=keys_map` passes (1 run). It also closes
finding 5 and part of finding 6. A test and a plant for the beep are owed
with it.

### 2. Blocking: no test reaches `wl_title` or `win_title` (measured)

Two plants of mine:

- `wl_title` does nothing: `make test TESTS=wl` passes.
- `win_title` never calls SetWindowTextW: `make win WIN=win` passes.

The PR's body says "Wine and the Wayland test compositor only check that the
call is made". Nothing checks that: `tests/test_wl.c` and `tests/test_win.c`
are unchanged by this PR, and `test_frames_main` uses its own backend. So the
two lines Davy will see the letters through are untested, on a feature whose
real-system check is still "by eye in the next trial build".

Asked: `test_wl` reads the title back from sway (`SWAYMSG` is there:
`swaymsg -t get_tree` has each window's `name`), `test_win` with
GetWindowTextW on the window it already finds, and a plant for each.

### 3. Blocking, one line: `title()`'s `"homeros"` format is dead (measured and by reading)

```c
snprintf(s, sizeof s, t->key ? "homeros [%c]" : "homeros", t->key);
```

`title()` returns early when `fr[i].key == t->key`. A slot's key starts at 0
(`windows()` zeroes a freed slot), a slot stays with one tab page for its
life, and a tab page's key never goes from a letter to 0 (`free_key()` sets
it once, `frame_key()` only stores a letter). So `t->key` is never 0 past
the early return. Plant: the second format changed to `"x"`,
`make test TESTS=frames_main` passes. A frame without a letter keeps the
title the backend opened it with, which is the same text. The top rule: the
format is `"homeros [%c]"` alone.

### 6. Suggestion: which keys are letters is written three times

`"abcdeghijklpqrstuvwxyz"` in `free_key()` (core), `k < 'a' || k > 'z' ||
strchr("fmno", k)` in `frame_key()` (keys), and the maps table that has
` 5f`, ` 5m`, ` 5n`, ` 5o`. A new SPC 5 key needs all three changed, and no
check says so when one is missed (the plant in core.txt covers `f` in core's
string only). Inside keys one function serves (the sketch). Across the two
packages, core naming keys' maps is the smell: `Tab.key`'s comment in core.h
lists SPC 5's keys. One owner would be keys asking core for "the first of
these letters no tab page has" or core.h exporting the string; thread 0's
call, not blocking.

The three-line ending of a map (`nlead = e->ks.pending = 0; hint_end();
normal_mappable(1);`) is now in `map()` twice. Under `make dupes`' size, so
the check is quiet; a review flags it. The sketch keeps it twice too; a
shorter shape is welcome.

### 7. For Davy, not blocking

- **Two names for a frame.** SPC 5 m still takes the frame's number in tab
  order (1 to 9), while the title and the jump use its letter. SPC 5 m
  {letter} would be one name, reach all 22 frames instead of 9, and drop the
  number parsing. It changes a key he has used, so it is his choice.
- **Where the letter shows.** Only in the OS window's title. Hyprland draws
  no title bar by default, and the terminal shows none (the tabline has no
  letters). **hypothesis** (his setup not seen): on the NixOS laptop the
  letter is visible only in a bar that shows the window title. The
  statusline could carry it.

### 8. Not this PR's: SPC, a group's key, then key 0 reads past the map's string (measured, on main too)

`reviews/pr-166-repro/test_zprobe_nul.c`: keys Space, `5`, 0. ASan:
global-buffer-overflow, READ of size 1, `map()` at `if (m[j])` (keys.c:305
here, :284 on main 9802abcb; 1 run each). `typed()` matches the 0 against
the string's terminator, so `j` is one past the end of `" 5"`. A terminal
sends key 0 for Ctrl-@ and Ctrl-Space (`src/tty/tty.c:111`). For package 5.
The sketch for finding 1 does not fix it (the probe on the sketch stops
there, after 21 cases as the PR says).
